# XR-099: открытая шара не замечает вернувшуюся сеть, онлайн только после перезахода

Фидбек 2026-07-10: зайти в директорию шары без сети (показан локальный список
с пометкой «Офлайн»), затем включить сеть. Список так и остаётся офлайновым,
пока шару не переоткроешь. Выделено из XR-096 отдельной задачей.

## Корень

Cache-first (XR-059) стреляет `fetchManifest` один раз при `openShare`: упал
запрос, значит до `closeShare`/повторного `openShare` новых попыток нет.
Навигация по папкам внутри шары состояние не трогает
([FilesViewModel.kt](../../xr-android/app/src/main/java/com/xrproxy/app/ui/files/FilesViewModel.kt),
`navigateTo`), поэтому вернувшаяся сеть ничего не меняет.

## Что сделать

Перезапрашивать манифест при открытой шаре, когда есть повод думать, что сеть
вернулась. Кандидаты (выбрать при реализации):

- колбэк `ConnectivityManager` на появление validated-сети -> повторный fetch,
  если открыта шара с `offlineLocal`;
- и/или ретрай с бэкофом, пока шара открыта в `offlineLocal` (например 10с,
  30с, 60с, дальше по минуте);
- по приходу свежего манифеста молча подменить список и снять пометку (код
  подмены уже есть в `openShare`, вынести и переиспользовать).

## Сделано

Взяты оба кандидата, они дополняют друг друга. Неудачный fetch манифеста по
сети или по молчащему агенту заводит в `FilesViewModel` тихий перезапрос с
бэкофом 10с/30с/60с (дальше по минуте), пока шара открыта и стоит в
`offlineLocal`; колбэк `ConnectivityManager` на появление дефолтной сети
перезапускает цикл через секунду, не дожидаясь шага бэкофа. Свежий манифест
молча подменяет список и снимает пометку (`applyFreshManifest`, тот же путь,
что у явного refresh, плюс доклад недокачанного в очередь), текущая папка
живёт в `currentPath` и подмену переживает. Ответ агента по существу (4xx,
истёкший доступ) ретраем не лечится и цикл не заводит.

## Доработка после проверки: персист манифеста (2026-07-25)

Владелец на проверке заметил, что суть глубже. Заходишь в шару онлайн, видишь
полный манифест, ходишь по нему. Выходишь, заходишь заново уже офлайн, и видно
только то, что скачано на телефон. Причина: кэшем cache-first служил лишь
список локальных файлов (`localManifest` обходит скачанное), сам серверный
манифест нигде не сохранялся. Ожидание владельца: показывать полный последний
манифест и офлайн, но честно пометить, что это оффлайн-снимок.

Сделано: последний удачный серверный манифест кладётся на диск
(`ShareRepository.saveManifestCache`, `filesDir/manifest-cache/<shareId>.json`)
при каждом успешном fetch (открытие, явный refresh, тихий ретрай). При открытии
шары cache-first грузит этот полный список (`loadManifestCache`) и показывает
его с пометкой офлайна; на локальные файлы падаем только когда кэша манифеста
ещё нет. Флаг `offlineFullListing` отличает «показан последний известный список»
от «показаны только скачанные файлы», плашка берёт нужный текст. Кэш чистится
при удалении шары (undo вернёт запись, полный список подтянется при следующем
онлайн-заходе).

## Проверка

1. В офлайне открыть шару со скачанными файлами, зайти в подпапку.
2. Включить сеть, шару не переоткрывать. Ожидаемо: в пределах десятков секунд
   список подменяется полным манифестом, пометка «Офлайн» уходит, текущая
   папка сохраняется.
3. Персист манифеста: онлайн открыть шару, дождаться полного списка, выйти.
   Выключить сеть, снова открыть ту же шару. Ожидаемо: виден весь список
   файлов (включая не скачанные), плашка «Офлайн: показан последний известный
   список». Не скачанные файлы видны, но по тапу на скачивание офлайн ждёт
   сеть. Раньше на этом шаге было видно только скачанное.

## Ревью

- заведённый цикл ретрая не останавливался на содержательных ошибках агента и долбил хаб через stale_token-ветку каждый круг: исправлено, цикл продолжается только на isOffline/isAgentOffline (060634c)
- offlineRetryJob мутировался из потока ConnectivityManager и main без синхронизации, возможна осиротевшая джоба: исправлено, колбэк прыгает в viewModelScope, вся работа с полем на main (060634c)
- сетевой провал явного refresh не ставил offlineLocal, и ретрай для этого пути был мёртвым кодом: исправлено, офлайн-исход refresh помечает шару offlineLocal (060634c)
- после провала refresh плашка «показаны только скачанные файлы» висела над полным серверным списком: исправлено, офлайн-провал refresh подменяет список локальным, как открытие без сети
