# XR-249: Цель: юзабилити контента шар в приложении: список файлов как проводник с сортировкой по имени и дате, дата добавления в списке, признак просмотрено после открытия, обрезка ютуб-суффикса [id] в отображении, удаление файлов из шары

## Цель

Повысить юзабилити работы с контентом шар в Android-приложении. Пять пунктов
постановки:

1. Список файлов шары ведёт себя как проводник: сортировка по имени и по дате
   изменения, за основу берутся механики популярных файловых менеджеров.
2. В списке видна дата добавления файла (сейчас не отображается вовсе).
3. У файла появляется признак «просмотрено», он ставится после открытия файла.
   Особенно важен для видео.
4. Импорт с ютуба оставляет в конце имени блок вида `[abcd...]`; в отображении
   он игнорируется, чтобы эллиптическое сокращение имени показывало полезную
   часть.
5. Файлы можно удалять из шары через приложение (импорт есть, удаления нет).

DoD: каждый пункт закрыт агентским экранным сценарием на эмуляторе (AVD
xr-test, uiautomator, порядок в памяти проекта): сортировка переключается и
меняет порядок списка, у файла видна дата добавления, после открытия видео у
него появляется признак «просмотрено», файл `Название [dQw4w9WgXcQ].mp4`
отображается без суффикса в скобках, удалённый через приложение файл пропадает
из списка и из шары на хабе. После зелёных сценариев цикл останавливается и
зовёт пользователя на финальную проверку на телефоне; закрывает цель
пользователь.

## Бюджет

бюджет: week_all <= 15
бюджет: week_max <= 10

Ярус не ограничен. Бакеты общие на машину: числа это верхняя граница трат
машины за время цикла, а не точный счётчик цели.

## Задачи цели

- [XR-250](archive/2026/XR-250.md): удаление файла из шары через приложение (пункт 5).
- [XR-251](XR-251.md): проводник как файловый менеджер, сортировка, дата,
  просмотрено, ютуб-суффикс (пункты 1-4), после XR-250.

Пункты 1-4 живут в одном экране и в одной строке списка, поэтому едут одной
задачей. Круг конвейера (исполнитель, ревью, сборка APK, прогон на эмуляторе)
стоит примерно одинаково при любом размере задачи, и четыре отдельные строки
заплатили бы за него четырежды. Удаление отделено, у него своя цепочка через
JNI и своя цена ошибки. Порядок последовательный, обе задачи правят `FileRow` и
`FilesViewModel`, параллельные ветки разъехались бы на слиянии.
