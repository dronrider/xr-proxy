# XR-231. Импорт из ютуба через системное «Поделиться»

## Мотивация

Импорт видео это основной сценарий импорта, а путь к нему сейчас длинный:
скопировать ссылку в ютубе, перейти в приложение, открыть диалог импорта,
тапнуть в поле, зажать тап ради меню вставки, вставить, нажать «Импортировать».
Семь действий и два приложения ради одной ссылки. У Android для этого есть
штатный механизм: кнопка «Поделиться» прямо в ютубе. Приложение должно
появляться в системном шите шаринга и принимать ссылку само, тогда весь путь
сжимается до двух-трёх тапов без буфера обмена вовсе.

## Что сейчас

Импорт живёт в диалоге на экране шары:
[FilesScreen.kt](../../xr-android/app/src/main/java/com/xrproxy/app/ui/files/FilesScreen.kt)
(`ImportDialog`, поле ссылки плюс чипы качества 720p/1080p/Максимум), запуск
через `FilesViewModel`. Извне приложение ссылки не принимает:
в [AndroidManifest.xml](../../xr-android/app/src/main/AndroidManifest.xml)
есть intent-filter'ы `VIEW` под invite-ссылки, а `SEND` нет. Поле ссылки
всегда пустое, из буфера ничего не подставляется.

## Что сделать

1. **Приём ACTION_SEND.** Intent-filter `ACTION_SEND` с `text/plain` на
   `MainActivity`. Ютуб кладёт в `EXTRA_TEXT` заголовок видео вместе со
   ссылкой, поэтому из текста вытаскивается первый http(s)-URL; шаринг без
   ссылки внутри вежливо отклоняется снекбаром.
2. **Шит импорта.** По приёму открывается компактный шит: выбор шары из тех,
   где есть право импорта (одна подходящая выбирается сама, последняя
   использованная запоминается и стоит по умолчанию), те же чипы качества,
   кнопка «Импортировать». Итоговый путь от ютуба: «Поделиться», иконка
   приложения, «Импортировать».
3. **После запуска** джоба уходит на агента, шит закрывается и пользователь
   остаётся в приложении на экране этой шары с привычной строкой прогресса.
   Механика запуска и трекинга общая с нынешним диалогом, дублировать её в
   шите не надо.
4. **Буфер как запасной путь.** В нынешнем диалоге импорта при открытии
   подставлять ссылку из буфера обмена, если там лежит http(s)-URL. Это
   убирает возню со вставкой и в старом сценарии. Читать буфер только в
   момент открытия диалога: на Android 12+ система показывает тост о чтении
   буфера, постоянный опрос выглядел бы как слежка.

Rust-части в задаче нет, вся правка клиентская (Android без автотестов по
правилам проекта).

## Развилки

- **Вернуться в ютуб или остаться.** Можно закрывать шит сразу и возвращать
  пользователя в ютуб, но тогда прогресс никто не видит, а джоба живёт лишь
  в памяти ViewModel (сирота при смерти процесса, та же болячка, что в
  XR-222). Первый заход оставляет пользователя в приложении на экране шары;
  «выстрелил и вернулся» имеет смысл только после XR-222 (переприкрепление
  к живой джобе) и XR-175 (очередь).
- **Direct Share** (ярлыки конкретных шар прямо в системном шите) в первый
  заход не берём: это отдельный API с шорткатами, живой спрос неясен.
- **Другие источники.** Фильтр не привязан к ютубу: та же кнопка
  «Поделиться» есть в любом браузере и приложении, агент сам решает, что
  умеет скачивать. Ограничивать по домену на клиенте не надо.

## Тексты UI (согласовать до реализации, урок XR-049)

- заголовок шита: «Импорт в шару»;
- подпись выбора шары: «Куда»;
- снекбар при шаринге без ссылки: «В переданном тексте нет ссылки»;
- кнопки те же, что в диалоге: «Импортировать», «Отмена».

## Сценарий проверки

Пользовательский, на проде:

1. В ютубе под видео нажать «Поделиться», выбрать приложение. Ожидаемо:
   открылся шит с выбранной по умолчанию шарой и качеством.
2. Нажать «Импортировать»: экран шары, строка прогресса, по завершении файл
   в листинге.
3. Поделиться текстом без ссылки (выделить абзац в браузере): снекбар про
   отсутствие ссылки, ничего не падает.
4. Старый путь: скопировать ссылку, открыть диалог импорта с экрана шары.
   Ожидаемо: ссылка уже стоит в поле, осталось нажать «Импортировать».
