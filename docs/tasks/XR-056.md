# XR-056: компактный общий индикатор очереди синка

Общего индикатора прогресса синка по сути нет, а место он занимает много.

## Проблема

Текущий
[ProgressBar](../../xr-android/app/src/main/java/com/xrproxy/app/ui/files/FilesScreen.kt#L468)
это Card во всю ширину про один файл: имя + полоса по байтам текущего файла +
скорость, а агрегат «файл N/M» втиснут мелким текстом.

## Что сделать

Компактный общий индикатор очереди: какой файл синкается сейчас, сколько
осталось (X из N), общий прогресс по батчу, стоп всей очереди. Компактно (одна
строка / тонкая полоса), не карточка на пол-экрана. Данные уже приходят в
`Progress` (`filesDone`/`filesTotal`/`file`, движок отдаёт
`files_done`/`files_total`), нужно агрегатное представление вместо по-файлового.
Детали конкретного файла (байты/скорость) из общего индикатора убрать, они
переезжают на строку файла (XR-044). Виден и для фонового синка, не только
foreground.

Смежно с XR-044 (та же панель/экран, прогресс на строках это предпосылка ужать
глобальный), логично делать в один заход.

Код:
[ui/files/FilesScreen.kt:468](../../xr-android/app/src/main/java/com/xrproxy/app/ui/files/FilesScreen.kt#L468),
[ui/files/FilesViewModel.kt:38](../../xr-android/app/src/main/java/com/xrproxy/app/ui/files/FilesViewModel.kt#L38)

## Решение

Общий индикатор это одна строка над списком: имя файла, который едет сейчас,
счётчик «X из N», кнопка «Стоп» и тонкая полоса по батчу под ними
(`SyncQueueBar` в `FilesScreen.kt`). Стоит он и на списке шар, и в проводнике:
очередь одна на все шары. Байты и скорость в него не вернулись, они уже живут на
строке файла после XR-044, там же и отмена одной строки.

Расчёт вынесен из экрана в чистый `ui/files/SyncProgress.kt` (`syncIndicator`,
без Android SDK) и покрыт JVM-юнитом. Прогресс считается по файлам, как и
просили: агрегатных байт на очередь экрана никто не отдаёт, каждый файл едет
своей передачей, а `bytes_total` снимка это либо один файл, либо весь проход
зеркала. Доля текущего файла всё же добавляется дробной частью к пройденным,
иначе батч из одного файла держал бы полосу в нуле до самого конца; берётся она
только у передачи про один файл и только когда снимок называет именно голову
очереди (зеркало могло держать лок и качать своё). Размер батча это пройденные
плюс оставшиеся: счётчик `queueDone` в состоянии растёт на каждом ушедшем из
очереди файле и обнуляется, когда новый батч встаёт в пустую очередь, поэтому
отменённая очередь не оставляет после себя вранья.

Фоновое зеркало считается по своему снимку (`files_done`/`files_total`).
Не показывался индикатор для него не из-за расчёта, а из-за опроса: цикл
`ensureTransferPolling` крутился, пока открыта шара, занята очередь или идёт
перенос хранилища, а на списке шар нет ни того, ни другого, ни третьего, и
`transfer` оставался пустым. Теперь опрос держится всё время, пока вкладка
«Файлы» на экране: `watchTransfers`/`unwatchTransfers` зовёт `DisposableEffect`
экрана, и флаг `screenOpen` входит в условие цикла.

«Стоп» новой механики не завёл: на своей очереди он гоняет по её элементам ту же
`cancelDownload`, что и крестик на строке (снятие с выбора, изъятие из очереди,
адресная отмена нативной передачи), а на фоновом синке с пустой очередью зовёт
существующую `cancelTransfer`. Перенос хранилища остался при своей карточке со
своим стопом, при нём общий индикатор прячется, чтобы не было двух полос разом.

## Сценарий проверки

Агентская часть: `cd xr-android && ./gradlew :app:compileDebugKotlin
:app:testDebugUnitTest`. Ожидание: сборка без новых предупреждений, восемь
тестов `SyncProgressTest` зелёные. Краснота проверена мутацией: если убрать
сверку головы очереди с файлом снимка, падает
`mirrorHoldingTheLockDoesNotLendItsProgressToTheQueue`.

Пользовательская часть, эмуляторный стенд с локальным агентом шары (такой
собирался для XR-175):

1. Поставить в очередь несколько файлов подряд плюсами на строках. Ожидание: над
   списком одна строка с именем текущего файла и «1 из 3», полоса ползёт, по
   мере готовности счётчик идёт «2 из 3», «3 из 3», карточки во всю ширину нет.
2. Нажать «Стоп». Ожидание: очередь пустеет целиком, индикатор пропадает,
   строки файлов возвращаются к плюсу, недокачанное остаётся на диске и плюс
   докачивает с места.
3. Выйти из шары на список шар и оттуда включить синк шары с несколькими
   недостающими файлами (или дождаться фонового прохода). Ожидание: та же строка
   индикатора видна и на списке шар, счётчик идёт по файлам прохода зеркала.
4. Начать перенос папки шары на устройстве. Ожидание: карточка переноса на
   месте, второй полосы над ней нет.
