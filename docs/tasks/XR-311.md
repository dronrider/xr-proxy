# XR-311: Android VPN перехватывает LAN и остаётся включённым в доверенной сети

## Что происходит

Android-клиент оставляет туннель включённым дома, хотя сеть отмечена как
доверенная. При включённом клиенте локальная страница роутера отвечает
ERR_EMPTY_RESPONSE, после отключения клиента открывается. Перехват на
роутере не видит попытки соединения телефона с тестовым портом.

В коде Android весь IPv4 направлен в TUN. В xr-core TCP-соединение с частным
адресом назначения закрывается с ошибкой. Поэтому доступ к LAN зависит от
состояния VPN. Причину несработавшей паузы нужно установить отдельно, с учётом
скрытого SSID, разрешений Android, восстановления сервиса и явного «включить здесь».

## Чего хотим

Локальные ресурсы доступны с включённым Android-клиентом без выхода через
VPS. В доверенной сети клиент автоматически снимает TUN, если пользователь
явно не выбрал продолжение работы в этой сети. Диагностика отличает паузу,
ручное исключение и невозможность узнать сеть.

## DoD

1. Устранён перехват LAN без нарушения туннельного DNS, fake DNS и IPv6.
2. Установлена и исправлена причина, способная оставить VPN включённым в
   доверенной сети. Неизвестный SSID не считается доказательством доверия.
3. Отдельные регрессии воспроизводят старое поведение и проходят после
   исправления. Проверены возврат домой, работа в фоне, уход на сотовую
   сеть и явное ручное исключение.
4. Сборка Android и доступные автоматические тесты выполнены. Подготовлена
   сборка для проверки на телефоне владельца, документация обновлена.

## Ранг

## Приёмка

- вид: mixed
- барьер «доступ»:
  - ADB не видит физический Samsung. Автоматические сценарии проверяют
    маршруты и состояние сервиса; поведение на устройстве подтверждает
    владелец установкой подготовленной сборки.

## Сценарий проверки

1. На Android с включённым VPN открыть страницу роутера или NAS в домашней
   IPv4-сети. До исправления соединение закрывалось; после исправления
   страница открывается без отправки запроса на VPS. Повторить с домашней
   сетью `10/8`, чтобы проверить отсутствие конфликта с виртуальным DNS.
2. В доверенной сети включить автоматическую паузу, открыть приложение,
   затем свернуть его. Туннель снимается, состояние показывает паузу.
   При недоступном SSID в журнале должна быть причина; вслепую паузы нет.
3. Нажать «включить здесь»: туннель остаётся включённым, LAN доступен.
   Вернуть автоматическую паузу и перейти в недоверенную сеть: клиент
   возобновляет работу. Проверить возврат домой и восстановление после
   перезапуска процесса, затем повторное открытие приложения.
4. На эмуляторе собрать приложение и instrumentation APK, установить оба
   и запустить собственный runner. Основной режим проверяет повышение
   foreground-типа восстановленного сервиса. Режим `-e lan true` проверяет
   настоящий TUN и опубликованные Android маршруты, адрес и DNS.

С настроенными `JAVA_HOME`, `ANDROID_HOME` и собранными JNI-библиотеками:

```sh
./xr-android/gradlew -p xr-android :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
adb install -r -t xr-android/app/build/outputs/apk/debug/app-debug.apk
adb install -r -t xr-android/app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -r -e lan true com.xrproxy.app.test/com.xrproxy.app.service.TrustedNetworkInstrumentation
```

Команды установки выполняются из корня проекта. Для эмулятора с более новой
установленной версией задать при сборке подходящий `-PxrVersionCode`, не
удалять приложение ради обхода проверки версии. При успешном прогоне runner
возвращает `passed=2` и `INSTRUMENTATION_CODE: -1`.

## Проверка

- `cargo test --workspace`: 1137 passed, 0 failed, предупреждений нет.
- `:app:testDebugUnitTest`: 61 тест, ошибок нет. Четыре новых теста проверяют
  исключения LAN, публичные адреса, границы служебного пула и покрытие CIDR.
- Для LAN отдельно подтверждены красные мутации: старый `0/0`, старый DNS
  в RFC1918 и конфликт виртуального адреса с выдаваемым fake DNS.
- `regcheck` на Android API 35: новое поведение прошло, база упала на
  отсутствии foreground-типа `location` после открытия UI. Тест использует
  настоящий Android-сервис без подключения к VPS.
- Независимое ревью кода не нашло блокеров. Проверены маршруты, IPv6,
  виртуальный DNS, поздний bind, разрешения и ручное исключение доверия.
- Android API 35, реальный TUN: `passed=2`, `INSTRUMENTATION_CODE: -1`.
  Проверены принятие адресов, DNS и фактические LinkProperties маршрутов.
  Доставка HTTP по LAN на физическом Samsung пока не проверена.

Чисто фоновое восстановление до первого открытия UI всё ещё зависит от
ограничений Android на чтение SSID. Неизвестное имя не считается доверенной
сетью. Условия сбоя паузы на телефоне владельца пока не установлены.
Для этого нужен журнал установленной версии и проверка подготовленной сборки.
