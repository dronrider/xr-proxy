# XR-178. Совместное редактирование текстовых шар: git как движок синка

Задача типа LLD: результат это спроектированное решение. Дизайн целиком в
[LLD-33](../lld/33-share-git-sync.md); исходный бриф с мотивацией и разбором
вариантов (git против своего merge поверх PUT/412) переехал туда же (шапка,
разделы 1 и 3), здесь остались ход работы и сценарий проверки. Реализация
режется на три задачи-фазы: агент (XR-188), харнесс синка (XR-189), web и
приложение (XR-190).

## Ход работы

- 2026-07-27: изучены write-контур LLD-28 и структурные операции LLD-32,
  relay-путь LLD-23, импорт LLD-29 (прецедент внешнего бинаря за опт-ином),
  роуты и гейты server.rs, харнесс pull/push (one-shot, без relay), подпись
  манифеста XR-046. Выяснено, что web-морды у шары нет вовсе (ссылка
  `xrshare://` понятна только приложению), а gitoxide на момент дизайна не
  умеет push, поэтому у харнесса libgit2, у агента спавн системного git.
  Написан LLD-33, строка добавлена в раздел 9 ARCHITECTURE.md, реализация
  заведена задачами XR-188/189/190.

## Сценарий проверки

Проверка пользовательская: согласовать дизайн.

1. Прочитать [LLD-33](../lld/33-share-git-sync.md).
2. Подтвердить развилки раздела 8: спавн pack-процессов у агента вместо
   http-backend/gitoxide и libgit2 у харнесса; git в PATH только на машине
   агента; репозиторий в данных агента с `core.worktree` и `updateInstead`
   (агент не мержит, мирится опоздавший харнесс); конфликт-копии вместо
   маркеров; long-poll подписанного HEAD; весь git-контур под `share:write`,
   включая fetch; «только текст» через колпак размера, а не пометку шары;
   правка из web по write-токену из гранта (`weblink`), минтинг не тронут.
3. Подтвердить разбивку реализации на три фазы (агент / харнесс / web и
   приложение) и состав задач XR-188/189/190.

Итог проверки: замечания правятся в LLD, после согласования задача
закрывается, реализация идёт по XR-188/189/190 отдельными чатами.
