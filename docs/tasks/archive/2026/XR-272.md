## Сценарий проверки

Спайк проверяется воспроизводимостью прогонов, а не юнит-тестом. Пользовательской
части (эмулятор) у спайка нет: iOS-устройства и Xcode на стенде нет, что
требует Xcode, помечено в LLD-39 разделах 1 и 4.6 и здесь не воспроизводится.

Агентская часть, прогоняется на macOS без Xcode (только Command Line Tools):

1. Окружение: Xcode нет, только CLT, iphoneos SDK не находится.

   ```
   $ xcode-select -p
   /Library/Developer/CommandLineTools
   $ xcrun --sdk iphoneos --show-sdk-path
   xcrun: error: SDK "iphoneos" cannot be located
   ```

2. Ставим iOS-таргет (rustup качает только `rust-std`, Xcode не нужен).

   ```
   $ rustup target add aarch64-apple-ios aarch64-apple-ios-sim
   info: installing component 'rust-std' for 'aarch64-apple-ios'
   info: installing component 'rust-std' for 'aarch64-apple-ios-sim'
   # exit 0
   ```

3. Сборка под таргет без обхода. Ожидаемый исход: компилируются чистые
   Rust-крейты, падает `build.rs` крейта `ring` на отсутствии iphoneos SDK для
   ассемблера. Это находка спайка: барьер в SDK, не в Rust-коде.

   ```
   $ cargo build -p xr-core --target aarch64-apple-ios --lib
      Compiling ring v0.17.14
      Compiling tokio v1.49.0
      Compiling serde v1.0.228
      ... (ed25519, rand_chacha, serde_json, heapless, der ... компилируются)
   warning: ring@0.17.14: xcrun: error: SDK "iphoneos" cannot be located
   error occurred in cc-rs: command did not execute successfully
     (status code exit status: 1): "xcrun" "--show-sdk-path" "--sdk" "iphoneos"
   error: failed to run custom build command for `ring v0.17.14`
   ```

4. Сборка под таргет с прозрачным обходом (даём `cc` присутствующий macOS SDK
   как sysroot, чтобы обойти падающий вызов `xcrun` для iphoneos). Ожидаемый
   исход: компилируется весь дерево и сам `xr-core`, объекты `ring` это arm64.
   Это диагностика совместимости Rust-исходников, а не годный iOS-бинарь.

   ```
   $ SDKROOT=$(xcrun --sdk macosx --show-sdk-path) IPHONEOS_DEPLOYMENT_TARGET=15.0 \
       cargo build -p xr-core --target aarch64-apple-ios --lib
      Compiling xr-core v0.1.0
       Finished `dev` profile [unoptimized + debuginfo] target(s)   # exit 0
   $ ls -la target/aarch64-apple-ios/debug/libxr_core.rlib
   -rw-r--r--  42957720  target/aarch64-apple-ios/debug/libxr_core.rlib
   $ file target/aarch64-apple-ios/debug/build/ring-*/out/*montgomery.o
   Mach-O 64-bit object arm64
   ```

5. Обычная сборка не сломана: `cargo test --workspace --exclude xr-client`
   зелёный, ноль warnings.

   ```
   $ cargo test --workspace --exclude xr-client
   test result: ok. 218 passed; 0 failed ...   # 783 passed суммарно по крейтам
   $ cargo test --workspace --exclude xr-client 2>&1 | grep "warning:" | grep -v "generated" | wc -l
   0
   ```

Прогон 2026-08-12 после слияния в main. Все пять шагов воспроизведены:
iphoneos SDK не находится (только CLT); iOS-таргет установлен; сборка под
aarch64-apple-ios без обхода падает ровно на build.rs крейта ring; с обходом
через macOS SDK собирается libxr_core.rlib 42.9 МБ, объекты ring это Mach-O
arm64; тест ios_memory_budget проходит и печатает те же числа (холостой туннель
+3.3 МБ, 256 простаивающих сессий +0.4 МБ то есть 2 КиБ на сессию, 64
прокачанных +8.0 МБ то есть 128 КиБ на сессию); воркспейс зелёный, ноль
warnings.

## Ревью

- Раздел 4 моделирует пик по числу сессий, но не называет постоянный базовый расход процесса расширения: резидентный код движка (xr-core+ring+rustls+tokio, релизный staticlib, а не 42МБ debug-rlib), простаивающий tokio-рантайм, арены и фрагментация аллокатора, состояние rustls/reqwest. Под 15МБ это ест бюджет ещё до первой сессии, и ни один рычаг 4.5 его не режет. Назвать эту статью в 4.3 хотя бы как неизмеренную константу (её ловит замер 4.6), иначе вывод «влезает после тюнинга» неполон именно в той части, ради которой спайк и заведён.: отклонено, Снято: ветка ушла вперёд на a0e60dc, раздел 4.7 меряет холостой туннель (+3.4МБ базовой цены) и правит переучёт простаивающих сессий (calloc-страницы ленивы), харнесс ios_memory_budget.rs это подтверждает прогоном. Замечание было против устаревшего 24f6f00.
