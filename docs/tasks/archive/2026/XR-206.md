# XR-206: Не-ASCII после звёздочки в правиле пресета валит весь парк: compile_rule не валидирует домены из пресета хаба и TOML (в отличие от пользовательских правил), опечатка вида *яндекс.рф даёт char boundary panic в routing.rs:205 на первом же SNI, роутеры и телефоны уходят в цикл падений

## Разбор

Корней два, и они складываются.

1. `matches_rule` резал суффикс по байтам: `hostname_lower == suffix[1..]` в
   расчёте на то, что нулевой байт это точка от `*.`. Суффикс без точки
   (`*яндекс.рф` компилировался в `яндекс.рф`) уводит срез внутрь двухбайтовой
   `я`, и это паника, а не ошибка разбора конфига. Ловит она первый же SNI, то
   есть весь парк уходит в цикл падений.
2. `compile_rule` брал домены как есть: пользовательские правила проходят через
   `user_rule::classify_pattern`, а пресет хаба и TOML не проверялись вообще.
   Рядом же битый CIDR давно отбраковывается с WARN, домены остались дырой.

## Решение

Матчинг больше не полагается на форму суффикса: `ends_with` плюс сравнение с
базой через `strip_prefix('.')`. Паника невозможна на любом входе, даже если в
`CompiledRule` каким-то путём попадёт мусор. Соседних срезов по строкам в
рабочем коде нет, остальные `[..]` идут по байтовым буферам протокола.

Домены из пресета и TOML прогоняются через ту же пару
`user_rule::normalize_pattern` + `classify_pattern`, что и пользовательские
правила. Выбран отказ с WARN, а не нормализация: непонятно, что имел в виду
автор правила (`*яндекс.рф` это и опечатка в `*.яндекс.рф`, и попытка написать
кириллицу вместо punycode), а молча додумывать маршрут для чужого трафика хуже,
чем не применить одно правило и написать об этом в лог. Отбраковка точечная,
соседние домены того же правила продолжают работать: одна опечатка в общем
пресете не должна ни ронять клиента, ни лишать весь парк маршрутизации.

Побочное следствие: домен теперь приводится к нижнему регистру с обрезкой
пробелов (раньше был только нижний регистр), а односложные суффиксы вроде
`*.local` отбраковываются, потому что валидатор требует минимум две метки. В
живых конфигах и пресетах таких правил нет, проверено по `configs/*.toml`.

Хаб при загрузке пресета домены по-прежнему не проверяет (только размер). Это
осознанно оставлено снаружи задачи: клиент не должен доверять хабу в любом
случае, а отдельная проверка на стороне хаба это удобство редактора, не защита.

## Ревью

- Сценарий проверки не ловит вторую половину фикса: молча отброшенное валидацией правило выглядит как «сайт перестал проксироваться», нужен шаг на пустой grep по Invalid domain в логе роутера: исправлено, добавлен шаг 6: пустой grep по Invalid domain в логе обоих роутеров
- Шаг 3 сверяет md5 пересобранного бинаря: путь сборки попадает внутрь, пересборка из другого каталога даст другой хеш при верном выкате: исправлено, шаг 3 сверяет хеш залитого файла, снятый до scp
- В лог клиента уезжает русский текст ошибки из classify_pattern, он написан для экрана «Правила» на Android, соседние записи tracing по-английски: исправлено, в лог уходит только домен, текст ошибки остаётся для UI
- Путь компиляции одиночной * (domains = ["*"] -> пустой суффикс) тестом через Router::new не закрыт, тест собирает CompiledRule руками: исправлено, добавлен test_bare_star_rule_matches_any_sni через Router::new
- ARCHITECTURE называет факт валидации, но не её границы (ASCII, минимум две метки, кириллица в punycode), они описаны только в configs/client.toml: исправлено, границы проверки описаны в разделе 6.1 ARCHITECTURE
- Абзац в ARCHITECTURE не перенесён по ширине и двоеточие в середине фразы читается как подмена тире: исправлено, абзац перенесён, фраза перестроена
- Коммит с исправлениями смешал код, долгоживущую доку и файл задачи под scope proto: исправлено, коммит разбит на три: код, ARCHITECTURE, файл задачи
- Ветка про CIDR в списке domains тестом не покрыта: исправлено, добавлен test_ip_range_in_domains_is_skipped

## Проверка

Сценарий агентский: все шаги выполняются с машины агента, итог объективный,
прода шаги не меняют.

1. Регресс краснеет на старом коде:
   `regcheck --base main --inline xr-proto/src/routing.rs -- cargo test -p xr-proto routing::tests`.
   Ожидание: «тест краснеет на main и проходит на текущем коде».
2. `cargo test --workspace --exclude xr-client` зелёный, `grep warning:` пусто.
3. На обоих роутерах (DE и RU) `md5sum /usr/bin/xr-client` совпадает с md5
   того файла, который реально ушёл `scp` (значение снимается один раз перед
   заливкой; пересобирать заново нельзя, путь сборки попадает в бинарь).
4. На обоих роутерах процесс живой (`pgrep xr-client`) и обе nft-таблицы на
   месте (`nft list tables | grep xr_`): `xr_proxy` и `xr_udp_relay`.
5. `logread | grep -i panic` пусто на обоих роутерах.
6. `logread | grep 'Invalid domain in config'` пусто на обоих роутерах: ни одно
   живое правило пресета и локального TOML новой проверкой не отброшено.
7. С мака (он сидит LAN-клиентом за роутером DE)
   `curl -s https://www.cloudflare.com/cdn-cgi/trace | grep '^ip='` отдаёт
   exit-IP основного VPS, то есть маршрутизация по пресету после подмены
   бинаря продолжает проксировать.

Android этой веткой не выкатывается: Kotlin не менялся, движок подхватит фикс
следующим APK. На телефоне до тех пор остаётся старая логика, но пресет прода
битых доменов не содержит, так что риска нет.
