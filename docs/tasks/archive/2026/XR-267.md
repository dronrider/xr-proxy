# XR-267: Фундамент фазы 2 браузерного входа: коннектор relay плюс pinned-TLS под hyper в xr-proto, сервисные ручки хаба (маршрут публикации, проверка пароля с лимитом попыток, статус) под общим секретом [web], раздел публикаций в admin UI и выкат живого хаба с реестром XR-262 (LLD-38 фаза 2)

## Ход работы

- Исполнение: субагент opus/medium по вердикту pick (квота: week_all 40%, снимок 20м назад, сдвига нет), 2026-08-06.
- Сделано в `xr-proto`: коннектор `relay_tls_connect(endpoint)` (relay-стрим по
  токену эндпоинта плюс pinned-TLS, готовый `AsyncRead + AsyncWrite` под hyper),
  `probe_agent_online` для вердикта о живости агента, тип `WebRoute` и
  `web_share_id`. В `xr-hub`: конфиг `[web] domain/shared_secret` и
  `[relay] splice_lifetime_secs`, служебные ручки `POST /api/v1/web/route`,
  `POST /api/v1/web/verify-password`, `GET /api/v1/web/status` под общим
  секретом, лимит попыток на пароль, админские `GET/DELETE
  /api/v1/admin/exposes` и раздел «Публикации» в admin UI.
- Дока: раздел 4.9 в `docs/ARCHITECTURE.md` (коннектор, ручки, конфиг `[web]`,
  модель доверия), списки ручек там же, раздел про wildcard и фронт в
  `docs/HUB-DEPLOY.md`, закомментированный `[web]` в `configs/hub.toml`.
- Ревью: субагент sonnet/high по вердикту pick (квота: week_all 40%, снимок 43м назад, сдвига нет), 2026-08-06.

## Решения

- **Пин берётся из relay-токена эндпоинта, а не отдельным аргументом.**
  `agent_pubkey` уже лежит в токене, которым хаб разрешил транзит, поэтому право
  на транзит и пин ключа не могут разъехаться в вызывающем коде. Отвергнут
  вариант `relay_tls_connect(endpoint, agent_pubkey)`: он позволяет передать
  ключ одного агента с токеном на другого, а ловить это пришлось бы ревью.
- **`tokio-rustls` уехал в фичу `relay-tls` крейта `xr-proto`.** Отвергнута
  отдельная фича под коннектор: её никто в дереве не включает, и инлайновые
  тесты коннектора не собирались бы в `cargo test --workspace` вовсе. Вес
  терпимый: это тонкая склейка над уже подтянутым rustls, тяжёлый `rcgen`
  по-прежнему живёт только в `xr-share`.
- **Живость агента хаб спрашивает у relay сам, открывая стрим и сразу закрывая
  его.** Дизайн говорит «хаб знает это от relay», но у relay нет служебного API,
  а его код по LLD не меняется вовсе. Проба идёт по существующему протоколу
  hello и стоит один RTT. Отвергнуты: своё состояние о живости в хабе (нужен
  хартбит, которого в протоколе нет) и правка relay ради статусной ручки (ломает
  главное обещание LLD-23 о неизменности relay).
- **`online` это `Option<bool>` с причиной рядом.** «Спросить не вышло» и
  «агента нет на связи» это разные ответы, а слитые в один они читаются как
  ложная тревога о выключенной машине.
- **Общий секрет едет в `Authorization: Bearer` и сравнивается постоянным
  временем** (`subtle`, он уже в зависимостях хаба). Отвергнут свой заголовок
  `X-Xr-Web-Secret`: лишнее имя без выигрыша, а `Bearer` привычен и curl-у, и
  клиенту фронта.
- **Проверка пароля переиспользует учётки админки через общий
  `auth::password_matches`.** Заодно из `login` ушёл дублирующий разбор хэша:
  два места проверки пароля разъехались бы на первой же правке.
- **Лимит попыток считается по имени владельца, три промаха свободны, дальше
  задержка удваивается до пяти минут.** Адрес браузера до хаба не доезжает (его
  видит только фронт), поэтому ключ на хабе может быть только именем; свой лимит
  на адрес фронт держит сам, как сказано в п. 3.2 дизайна.
- **Ручки, чувствительные ко времени, вынесены в вариант с явным «сейчас»**
  (`verify_password_at`) **и с внешней пробой** (`status_with`): тест двигает
  время сам и не спит, а поход на relay проверяется там, где он живёт, в
  `xr-proto`.
- **Раздел админки снимает любую публикацию, а не только свою.** Реестр общий на
  хаб, и поддомен надо освобождать в том числе с выключенной машины агента,
  мандата которого у владельца хаба под рукой нет.

## Тесты

- `xr-proto`: `test_relay_tls_connect_pins_agent_key` (настоящий rustls-агент за
  сплайсом тестового relay: верный пин несёт байты, чужой SPKI роняет хендшейк),
  `test_probe_agent_online_reads_hello_verdict` (agent-offline это `false`,
  успешный hello это `true`, мёртвый relay это ошибка, а не вердикт).
- `xr-hub`: `web_route_is_gated_by_shared_secret` (без секрета и с чужим отказ,
  с верным маршрут с `share_id = web:dash`, мандат бьётся только со своей
  публикацией, без `[web]` ручка отвечает `503`),
  `web_verify_password_rate_limits_attempts`, `web_status_shows_publications_and_liveness`,
  `admin_sees_and_removes_any_publication`.
- Краснота проверена мутациями: гейт секрета «всегда Ok» и снятый лимит роняют
  три хабовых теста, подмена пина на чужой ключ роняет тест коннектора.

## Сценарий проверки (агентский)

Стенд поднимается локально, VPS не нужен. `$S` это любой пустой каталог.

```bash
cd <worktree>
cargo test --workspace --exclude xr-client            # зелёный, 0 warnings
cargo build -p xr-hub -p xr-relay

HASH=$(./target/debug/xr-hub hash-password 'owner-secret' | tail -1)
mkdir -p $S/data
openssl genpkey -algorithm ed25519 -out $S/k.pem
openssl pkey -in $S/k.pem -outform DER | tail -c 32 | base64 > $S/signing_key
cat > $S/config.toml <<EOF
[server]
bind = "127.0.0.1:18099"
data_dir = "$S/data"
[admin]
[[admin.users]]
username = "owner"
password_hash = "$HASH"
[signing]
private_key = "$S/signing_key"
[relay]
addr = "127.0.0.1"
port = 18444
splice_lifetime_secs = 900
[relay.obfuscation]
key = "dGVzdC1rZXktMzItYnl0ZXMtbG9uZy1lbm91Z2ghISE="
[web]
domain = "web.example.com"
shared_secret = "s3cret"
EOF
./target/debug/xr-hub --config $S/config.toml & sleep 2
B=http://127.0.0.1:18099/api/v1
```

Ожидания:

1. `curl -s -o /dev/null -w '%{http_code}\n' $B/web/status` это `401`, он же с
   `-H 'Authorization: Bearer wrong'` тоже `401`, а с `-H 'Authorization: Bearer
   s3cret'` это `200` и `[]`.
2. Завести публикацию (логин владельца, reg-token в админке, `share/exchange`,
   `expose/add --name dash`), затем
   `curl -s -H 'Authorization: Bearer s3cret' -d '{"publication":"dash"}' -H
   'content-type: application/json' $B/web/route` отдаёт `WebRoute`, где
   `relay_token.share_id` равен `web:dash`, `splice_lifetime_secs` равен `900`, а
   `expose_token.publication` равен `dash`.
3. `curl ... -d '{"username":"owner","password":"nope"}' $B/web/verify-password`
   это `{"ok":false}`, тот же запрос с `owner-secret` это `{"ok":true}`; пять
   промахов подряд дают `429` с временем ожидания.
4. Статус без relay: `online` это `null` и `probe_error` про недоступный relay.
   Поднять `xr-relay` с `hub_pubkey` из `GET $B/public-key`, портом 18444 и той
   же обфускацией: тот же `curl` отдаёт `"online": false` (агент не
   зарегистрирован), а `host` равен `dash.web.example.com`.
5. Админка: `GET $B/admin/exposes` под сессией владельца показывает `dash`,
   `DELETE $B/admin/exposes/dash` отдаёт `204`, после чего `web/route` на `dash`
   отвечает `404`. В UI это раздел «Публикации» (отладочная сборка отдаёт
   заглушку admin UI, для глаз собрать `cd xr-hub/admin-ui && npm ci && npm run
   build`).

Прогнано на этом стенде 2026-08-06: все пять пунктов сошлись, включая
`"online": false` от живого relay.

## Что осталось за задачей

Выкат хаба на прод катит диспетчер после слияния (нужен релизный бинарь с
собранным admin UI). Сам фронт `xr-web` это XR-263, апгрейд и живучесть XR-264.

## Проверка после выката

Прогнано диспетчером цели XR-266 на слитом коде, стенд по сценарию выше
(хаб `127.0.0.1:18099`, relay `127.0.0.1:18444`, агент из `install --token`),
2026-08-06.

```
1. web/status без секрета 401, с чужим 401, с верным 200 и []
2. web/route на dash: relay_token.share_id = web:dash,
   splice_lifetime_secs = 900, expose_token.publication = dash,
   приватного ключа хаба в ответе нет
3. verify-password: {"ok":false} на неверный, {"ok":true} на верный,
   пятая попытка подряд уходит в 429
4. web/status без relay: online = null, probe_error про недоступный relay;
   с живым relay: online = false, host = dash.web.example.com
5. admin/exposes под сессией владельца показывает dash, DELETE отдаёт 204,
   после него web/route на dash отвечает 404
```

Пункт 4 с первого раза дал `null` и «server closed during mux init»: в стендовом
`relay.toml` были заданы `salt` и `modifier`, а хабу оставлены дефолты, и
обфускация не сошлась. С одинаковыми настройками обеих сторон пункт сходится,
к коду отношения не имеет.

Хаб выкачен на оба узла: релизный бинарь собран `CARGO_TARGET_DIR=target-cross
cross build --release --target x86_64-unknown-linux-musl -p xr-hub` после
`npm ci && npm run build` в admin-ui, md5 `6b19e09b7ccf794aaaf2ec773efa02d9`
совпал на обоих, прежние бинари в `/usr/local/bin/xr-hub.bak.<ts>`. На обоих
`api/v1/relay` отдаёт 200, а `api/v1/web/status` отдаёт 503: блок `[web]` в
боевых конфигах не заведён, домен и общий секрет проставляются вместе с
выкатом `xr-web` (XR-263).
