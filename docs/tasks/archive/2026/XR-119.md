# XR-119: Выбор пресета хаба из приложения: карточка пресета на экране правил даёт выбрать пресет активного сервера из списка хаба (GET /api/v1/presets), выбор пишется в hubPreset профиля и применяется при следующем подключении; сейчас пресет назначается только инвайтом

Сейчас пресет активного сервера назначается только инвайтом. Даём выбрать его на экране правил из списка, который отдаёт хаб.

## Разбор данных

- **API хаба.** `GET /api/v1/presets` публичный, без авторизации ([xr-hub/src/api/presets.rs](../../xr-hub/src/api/presets.rs)), отдаёт массив `PresetSummary` ([xr-proto/src/preset.rs](../../xr-proto/src/preset.rs)): `name`, `version`, `updated_at` (rfc3339), `rules_count`. Описания в сводке нет (оно только в полном `Preset` через `GET /api/v1/presets/{name}`).
- **Поле профиля.** `ServerProfile.hubPreset: String` (имя-слаг) уже есть, сериализуется в `SharedPreferences` через [ServerRepository](../../xr-android/app/src/main/java/com/xrproxy/app/data/ServerRepository.kt). Из инвайта пишется в [VpnViewModel.kt:1018](../../xr-android/app/src/main/java/com/xrproxy/app/ui/VpnViewModel.kt#L1018). Смена сводится к `repo.upsert(server.copy(hubPreset = chosen))`.
- **Применение.** `buildConfigJson` читает `hubPreset` при сборке конфига на `nativeStart`, поэтому запись в профиль подхватывается на следующем подключении сама. При живом туннеле показываем подсказку «применится при следующем подключении» (как для «моих правил»).
- **Чего нет.** Вызова «список пресетов» на устройстве. Kotlin только читает кэш активного пресета; листинг `PresetSummary[]` живёт лишь внутри `PresetCache::refresh` в xr-core и JNI-экспорта не имеет.

## План

**UI (спроектирован в Claude Design, «Пикер пресета»).** Пикер на карточке пресета в секции «Серверные правила» (XR-120). Список пресетов открывается bottom sheet, строка это имя + «N правил, vX», текущий отмечен; тап пишет выбор и закрывает sheet. Аффорданс открытия согласовать с владельцем (1a дропдаун на имени / 1b кнопка «Сменить»).

**Код.**
1. xr-core: публичный хелпер, который GET-ит `/api/v1/presets` и возвращает `Vec<PresetSummary>` (вынести из `PresetCache::refresh`).
2. xr-android-jni: экспорт `nativeListPresets(hubUrl, timeoutMs)` по образцу `nativeListShares`, отдаёт JSON-массив сводок.
3. Kotlin: обёртка в `VpnViewModel` (`listPresets(hubUrl)`), состояние загрузки и ошибки, bottom sheet, запись `repo.upsert(server.copy(hubPreset = chosen))`, подсказка про следующее подключение при живом туннеле.

## Проверка

1. На экране правил открыть выбор пресета: приходит список с хаба, текущий отмечен.
2. Выбрать другой пресет: карточка показывает новое имя, при живом туннеле видна подсказка про следующее подключение.
3. Переподключиться: маршрутизация идёт по новому пресету (проверяемо по exit-поведению домена из нового пресета).
4. Хаб недоступен: понятная ошибка вместо пустого списка.
