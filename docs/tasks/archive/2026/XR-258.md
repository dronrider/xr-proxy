# XR-258: Группировка списка файлов: переключатель режимов, группы по дате и по источнику [после XR-256]

Задача цели [XR-253](../../XR-253.md), пункт 4 постановки и последняя из пяти.
Меню вида в шапке уже стоит (XR-256), метаданные с источником уже приезжают
(XR-255), макет утверждён владельцем (XR-254).

## Что сделать

По фреймам 3 (меню вида), 4 (группы по дате) и 5 (группы по источнику с
включённым фильтром) страницы «Проводник шары» проекта Claude Design
«Мобильное приложение шар».

1. **Режимы в меню вида.** К пункту «Только непросмотренные» добавляется группа
   «Группировка» с тремя взаимоисключающими пунктами: «Без групп», «По дате»,
   «По источнику». Выбор живёт в `ShareStore` тем же паттерном, что порядок
   строк и фильтр: один на все шары и переживает перезапуск. Иконка меню
   подсвечивается, когда список собран не как обычно.
2. **Группы по дате** строятся по дате из манифеста заголовками «Сегодня», «На
   этой неделе» и дальше по месяцам, со счётчиком в заголовке группы.
3. **Группы по источнику** берут `meta.source` (для видео это канал). Файлы без
   источника собираются в свою группу «Без источника» и идут последними, а не
   прячутся.
4. **Сортировка и группировка не мешают друг другу.** Группировка задаёт
   порядок групп, сортировка работает внутри группы, кнопка сортировки остаётся
   на своём месте и живёт своей жизнью.
5. **Папки при группировке.** Решение принимает задача и записывает в файл:
   папки в группу по источнику не ложатся (источника у них нет), и терять их
   нельзя, иначе в них не зайти. Разумный ход это держать папки отдельным
   блоком сверху, но проверить его на живом экране.

Тексты в макете сняты с кода дословно, менять их не надо.

## Сценарий проверки

Агентский, на эмуляторе. Стенд поднимается по
[local-docs/android-stand/README.md](../../../../local-docs/android-stand/README.md),
снапшот `xr-ready`, приёмы работы с `uiautomator` в памяти проекта. В шаре
нужны файлы разных дат, файлы с разными источниками и файлы без источника.

1. «По дате» собирает список группами с заголовками и счётчиками, порядок групп
   от свежих к старым.
2. «По источнику» собирает группы по каналам, файлы без источника лежат в своей
   группе последними.
3. Переключение сортировки при включённой группировке меняет порядок внутри
   группы, а не ломает сами группы.
4. Выбранный режим переживает перезапуск приложения.
5. Фильтр непросмотренных и группировка работают вместе: список остаётся
   сгруппированным, плашка фильтра на месте.
6. Папки не пропадают ни в одном режиме, в них по-прежнему можно зайти.

Вывод команд и снимки дерева класть в файл задачи реальные, а не пересказом.

### Что сделано

`FileGrouping { NONE, DATE, SOURCE }` и раскладка уровня по группам живут в
`model/Share.kt` рядом с `explorerLevel`: `explorerRows` превращает готовый
(отсортированный и отфильтрованный) уровень в список `ExplorerRow.Header` и
`ExplorerRow.Node`, а ленивый список рисует их одной лентой. Режим хранится в
`ShareStore` ключом `explorer_grouping` рядом с порядком строк и фильтром,
`FilesViewModel.setGrouping` пишет его туда же, откуда читает `init`.

Порядок групп задаёт сама группировка: по дате это «Сегодня», «На этой неделе»
и дальше по месяцам от свежих к старым, по источнику группы стоят по своему
самому свежему файлу. Файлы без источника (и без даты, если `mtime` нулевой)
собираются группой в конце. Сортировка при этом не тронута: она работает внутри
группы и живёт своей кнопкой.

**Папки при группировке.** Ни в группу по источнику, ни в группу по дате папки
не ложатся: своей даты у папки нет, источника тем более, а спрятать их нельзя,
иначе в них не зайти. Они идут блоком «Папки» сверху, со своим заголовком и
счётчиком: без заголовка непонятно, почему первые строки стоят выше всех групп.
На живом экране блок проверен во всех трёх режимах, в папку из него заходят.

## Ревью

- explorerRows/dateGroup/sourceGroup в model/Share.kt - чистая Kotlin-логика без Android SDK (границы Сегодня/На этой неделе/по месяцам, ранжирование групп), сложная и без единого теста; по памяти проекта именно такой код (нетривиальная чистая Kotlin-логика) исключение из запрета на автотесты Android и должен покрываться JVM-unit (границы недели/полуночи, будущие даты, нулевой mtime, пустой/пробельный source, порядок групп, стабильность порядка внутри группы): исправлено
- sourceGroup (model/Share.kt) использует само значение meta.source как ключ группы, а сентинел для "без источника" это буквальная строка "none": файл с реальным source="none" (правдоподобное имя канала/автора) схлопнется с группой Без источника по общему ключу, унаследует её ранг по maxOf (mtime вместо Long.MIN_VALUE) и перестанет уходить последним - ломает требование постановки п.3. Ключ сентинела нужен вне домена реальных source, например как у ExplorerRow.Header с ведущим \u0000: исправлено

### Правки по ревью

**Замечание 2, коллизия ключа.** Сентинел безымянной группы уехал за пределы
домена реальных значений: `NO_GROUP_KEY = "\u0000none"`, нулевой байт не
встречается ни в имени источника, ни в пути файла. Заодно закрыт соседний
случай той же природы: заголовок группы ключевался своим названием, поэтому
канал по имени «Без источника» дал бы две строки с одним ключом и уронил бы
ленивый список. `ExplorerRow.Header` теперь несёт ключ группы отдельным полем,
а блок папок ключуется `\u0000folders`.

**Замечание 1, тест.** Заведён `testImplementation("junit:junit:4.13.2")` и
`app/src/test/java/com/xrproxy/app/model/ShareGroupingTest.kt`, девять тестов на
`explorerRows`: список без групп, порядок групп по дате с границей полуночи и
воскресенья, начало недели по локали, дата из будущего, порядок групп по
источнику от свежих с пустым и пробельным `source` в конце, оба случая
коллизии, блок папок в обоих режимах и пустой уровень. Время и локаль тест
фиксирует сам: начало недели берётся из региона локали, и у `ru` без региона
