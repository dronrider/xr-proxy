# XR-168. Структурирование шары с устройства: директории, move/copy

Задача типа LLD: результат это спроектированное решение. Дизайн целиком в
[LLD-32](../lld/32-share-structure.md); исходный бриф с разбором текущей
модели переехал туда же (разделы 1 и 3), здесь остались ход работы и
сценарий проверки. Реализация заведена отдельной задачей XR-185, оптимизация
синка под серверный move это XR-169.

## Ход работы

- 2026-07-26: изучены manifest.rs/server.rs/safepath.rs агента, write-контур
  LLD-28, план и применение зеркала в xr-core, JNI-мост и экран Files
  приложения (write-обёрток в JNI ещё нет, гейт по scope только canImport,
  дерево строится из префиксов путей в Kotlin). Написан LLD-32, строка
  добавлена в раздел 9 ARCHITECTURE.md, реализация заведена как XR-185.

## Сценарий проверки

Проверка пользовательская: согласовать дизайн.

1. Прочитать [LLD-32](../lld/32-share-structure.md).
2. Подтвердить развилки раздела 8 (dirs отдельным списком и все, а не только
   пустые; занятая цель 409 без перезаписи; copy только файла; rename это
   move; scope остаётся share:write; без If-Match у операций структуры).
3. Подтвердить тексты UI из п. 2.5 (урок XR-049: тексты согласуются до
   реализации): «Новая папка»/«Название»/«Создать», «Переместить»,
   «Копировать», «Переименовать», пикер «Куда переместить?»/«Куда
   скопировать?» с кнопкой «Сюда», тосты «Папка создана»/«Перемещено»/
   «Скопировано»/«Переименовано».

Итог проверки: замечания правятся в LLD, после согласования задача
закрывается, реализация идёт по XR-185 отдельным чатом.
