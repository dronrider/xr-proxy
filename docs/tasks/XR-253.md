# XR-253: Цель: медиатека шары в приложении: двухстрочное имя вместо эллипса, метаданные файла с источником и каналом, заметный признак просмотрено с фильтром, группировка по дате и источнику

## Цель

Продолжение XR-249: проводник шары уже умеет сортировку, дату и признак
просмотрено, но владелец посмотрел экран списка файлов и назвал четыре
доработки.

1. Эллипс посередине имени решение неудачное: имя показывается в две строки, а
   компактность вида сохраняется, высота строки списка меняется незначительно.
   Экран предварительно дизайнится в Claude Design и согласуется с владельцем
   до реализации.
2. По видео не хватает информативности: понравившееся видео негде посмотреть,
   откуда оно скачано, и нет ссылки на страницу канала автора. Нужны
   элементарные метаданные файлов медиатеки и экран информации о файле, где
   видно всё, что о нём известно. Импорт по URL (LLD-29) пишет метаданные сам,
   а по уже скачанным файлам делается разовое дозаполнение тем, что удаётся
   вытащить.
3. Глазик просмотренности серый и почти незаметен; кроме того, отобрать одни
   непросмотренные нельзя.
4. Нет группировки записей, нужен компактный переключатель режимов отображения
   как в файловых проводниках: группировка по дате и группировка по источнику
   (у видео это канал), плюс фильтр по просмотренным.

DoD: каждый пункт закрыт агентским экранным сценарием на эмуляторе (AVD
xr-test, uiautomator, порядок в памяти проекта). Длинное имя файла видно в две
строки без эллипса посередине, высота строки списка выросла не больше чем на
треть; у импортированного видео открывается экран информации с источником и
ссылкой на канал, а у файла, скачанного до этой цели, тот же экран показывает
дозаполненное либо честно пустое поле; просмотренный файл отличим от
непросмотренного в списке, а фильтр оставляет только непросмотренные;
переключатель режимов собирает список группами по дате и группами по
источнику. После зелёных сценариев цикл останавливается и зовёт владельца на
проверку на телефоне; закрывает цель владелец.

Дизайн двухстрочной строки списка и экрана информации о файле цикл сам не
утверждает: макет уходит в Claude Design, и виток выходит `wait-human` до
ответа владельца.

## Бюджет

бюджет: week_all <= 15
бюджет: week_max <= 10

машины за время цикла, а не точный счётчик цели.

## Задачи цели

- XR-254: дизайн проводника в Claude Design, один макет на все четыре пункта
  постановки, чтобы владельца звать один раз, а не на каждый экран. Кончается
  согласованием, дальше реализация идёт по утверждённому. Закрыта: владелец
  выбрал вариант Б признака просмотра, точку у непросмотренного в левом
  отступе строки. Остальное в макете принято как есть.
- XR-255: метаданные файлов шары. Пишет их агент при импорте, отдаёт клиенту
  вместе с листингом, по уже скачанным файлам разовое дозаполнение. Фундамент
  для XR-257 и XR-258, едет параллельно дизайну. Закрыта, агент опубликован
  тегом xr-share-v0.3.8 на оба хаба.
- XR-256 (после XR-254): строка списка, пункты 1 и 3 постановки.
- XR-257 (после XR-254, XR-255): экран информации о файле, пункт 2.
- XR-258 (после XR-255, XR-256): группировка и переключатель режимов, пункт 4.
  После XR-256 не по смыслу, а по файлу: обе правят шапку списка.
