## Из черновика XR-294 «Страница шары на публичном пути берёт токен из фрагмента, а не из query» (записан 2026-09-06)

### Черновик

#### Ситуация

XR-198 оставила share-токен в query `?token=` и закрыла утечку маскировкой в
логах: фронт nginx пишет `access_log` форматом `xr_masked`, страница отдаётся
с `Referrer-Policy: no-referrer`. LLD-38 п. 2.6 (XR-265) выводит страницу
шары на `https://s.<web-домен>/{share_id}/...` через тот же nginx, и гейтом
там назван `ShareToken` из query.

#### Осложнение

На публичном пути каждый заход по ссылке проходит через фронт, и секрет
держится только дисциплиной его конфига: `error_log` при `502` пишет строку
запроса как есть, а любой промежуточный прокси или CDN логирует URL по своим
правилам. Маскировка закрывает наш nginx, а не путь целиком.

#### Вопрос

Отдавать страницу-оболочку без гейта и брать токен из `location.hash`
(`/web#token=`), чтобы фронт не видел его даже на первом заходе? Ссылкам
скачивания токен по-прежнему нужен, им остаётся query; вариант с кукой
тянет эндпоинт обмена и разбор CSRF на PUT/DELETE агента.

#### Гипотеза

Публичная ссылка `weblink` несёт токен во фрагменте, страница шары открывается
без токена в строке запроса к серверу, и в `access.log` фронта у захода на
страницу секрета нет вовсе.
