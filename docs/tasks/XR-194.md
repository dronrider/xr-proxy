# XR-194: Admin-сессии хаба живут вечно: нет TTL, ручки logout и лимита, утёкший Bearer действует до рестарта, а карта sessions только растёт

## Что происходит

Admin-сессии хаба бессрочные: TTL нет, ручки logout нет, лимита на оператора
нет. Утёкший Bearer работает до рестарта процесса, а карта сессий только
растёт.

## Чего хотим

Сессия живёт ограниченно (TTL), оператор может её погасить сам (logout),
число сессий на оператора ограничено. Задача из состава цели XR-286,
конвейер идёт по её файлу.

## DoD

- Сессия истекает по TTL и после этого отвергается; logout гасит токен,
  погашенный Bearer больше не проходит; лимит сессий на оператора
  вытесняет старейшую, а не растёт бесконечно.
- Поведение покрыто тестом стенда xr-hub (истечение, logout, лимит).

## Тесты

- Исключение: тесты (тесты в ветке есть: юнит-модуль `#[cfg(test)]` нового
  `xr-hub/src/sessions.rs` и три интеграционных теста в `#[cfg(test)] mod
  tests` файла `xr-hub/src/api/mod.rs`, но ворота слияния узнают тестовые
  файлы по суффиксам `_test.go/.py/.sh`, а Rust-овские модульные тесты в тех
  же файлах не видит).

## Ревью

- Ранг разошёлся со строкой доски: файл говорит 25+4+3+0+2 = 34, строка в docs/TASKS.md говорит 35 (25+6+2+0+2), а у соседних задач цели (XR-193, XR-239) разборка в файле совпадает со строкой. Ранг держит строка доски средствами taskctl, файл обязан её повторять: свести к одной правде, либо вернуть в файл разборку строки, либо обновить строку с основанием для новых чисел.: исправлено, файл сведён к разборке строки доски 25+6+2+0+2 = 35, причины пересобраны под эти числа
- Сценарий ссылается на пароль админки из secretctl, но такого секрета в хранилище нет: secretctl names содержит только пароли дашборда devkit, а HUB-DEPLOY.md и xr-setup оставляют пароль админки в /etc/xr-hub/admin.pass на хабе. Назвать конкретное имя секрета и положить значение в хранилище или брать пароль с хаба по ssh, иначе шаг 1 после выката упирается в отсутствующее значение.: исправлено, шаг 1 берёт пароль с хаба по ssh из /etc/xr-hub/admin.pass, secretctl из сценария убран

Прогоны ревью. regcheck командой из «Хода работы» повторён. На main он
красный, на ветке зелёный. `cargo test --workspace` целиком зелёный,
предупреждений ноль. Контрольная мутация: проверка `expires_at` в
`validate` заменена на безусловную годность. Оба теста истечения
покраснели, после отката зелёный вернулся. `taskctl lint` зелёный. Хук
символов на изменённых файлах ругается только на старые строки.

По существу. `insert`, `validate` и `remove` идут под одним write-локом,
вытеснение и вставка атомарны. Часы инъектируются, протухшая сессия
снимается при `validate` и подметается при `insert`. Logout сидит за
`require_admin` и гасит только предъявленный токен. Лимит вычистку
протухших учитывает и вытесняет старейшую по `seq` только у того же
оператора. Дефолты 12 часов и 5 сессий задокументированы в
`configs/hub.toml` и `ARCHITECTURE.md`. Сессии как были в памяти, так и
остались, serde-дефолты старый конфиг не ломают. admin-ui на 401 от
`/auth/*` не уходит в редирект.

Второй проход, оба замечания закрыты. Ранг в файле сведён к строке доски.
Оба пишут 25+6+2+0+2 = 35, расхождения нет. Причины ложатся на шкалу
RANKING.md. Ценность 6 это ощутимое улучшение, которого ждут или просят.
Неопределённость 2 это развилки только в деталях при предопределённом
подходе. Шаг 1 сценария берёт пароль с самого хаба, из
`/etc/xr-hub/admin.pass`. Путь совпадает с HUB-DEPLOY.md и действием
xr-setup, ссылка на отсутствующий секрет убрана. `taskctl lint` зелёный.

## Сценарий проверки

Агентский, после выката (адрес хаба из `.devkit/deploy.local`; пароль
админки установщик оставляет на самом хабе, в `/etc/xr-hub/admin.pass`):

1. `PASS=$(ssh root@$HUB cat /etc/xr-hub/admin.pass)` снимает пароль с хаба,
   затем `TOK=$(curl -s https://$HUB/api/v1/auth/login -H 'Content-Type: application/json' -d "{\"username\":\"admin\",\"password\":\"$PASS\"}" | python3 -c 'import json,sys; print(json.load(sys.stdin)["token"])')`
   выдаёт непустой токен.
2. `curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOK" https://$HUB/api/v1/admin/invites` печатает `200`.
3. `curl -s -o /dev/null -w '%{http_code}\n' -X POST -H "Authorization: Bearer $TOK" https://$HUB/api/v1/auth/logout` печатает `204`.
4. Повтор шага 2 тем же токеном печатает `401`: погашенный Bearer больше не проходит.
5. Шесть входов подряд (шаг 1 в цикле) и запрос админ-ручки первым из шести токенов: ответ `401`, старейшая сессия вытеснена лимитом (default 5). Истечение по TTL на живом хабе ждать 12 часов, его закрывают тесты ветки.
