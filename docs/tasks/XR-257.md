# XR-257: Экран информации о файле шары: источник, ссылка на канал, всё известное о файле

Задача цели [XR-253](XR-253.md), пункт 2 постановки. Метаданные до приложения
уже доезжают (XR-255), макет утверждён владельцем (XR-254).

## Что есть сейчас

Долгий тап по строке файла открывает диалог «Файл» из трёх строк: путь, размер
и обрезанный SHA-256
([FilesScreen.kt:779](../../xr-android/app/src/main/java/com/xrproxy/app/ui/files/FilesScreen.kt#L779)).
Ни даты, ни признака просмотра, ни тем более источника там нет, а метаданные
импорта в такой диалог не влезают.

Агент с версии `xr-share-v0.3.8` отдаёт у строки манифеста необязательное поле
`meta` (`url`, `source`, `source_url`, `published`, `title`): у импортированного
по ссылке оно заполнено, у скачанного до этой цели там либо одна ссылка на
ролик, собранная из суффикса `[id]` в имени, либо ничего. Поле едет под
подписью манифеста и уже доступно на стороне Kotlin через JNI.

## Что сделать

Диалог заменяется экраном по фрейму 7 (файл с источником) и фрейму 8 (файл без
метаданных) страницы «Проводник шары» проекта Claude Design «Мобильное
приложение шар».

1. **Экран вместо диалога.** Открывается тем же долгим тапом и вдобавок обычным
   тапом по нескачанному файлу: сейчас такой тап не делает ничего, а скачанный
   файл по-прежнему открывается сразу. Имя показывается целиком, обрезать его
   на своём экране нечем и незачем.
2. **Блок «Файл»**: путь в шаре, размер, дата, признак просмотра, начало
   SHA-256. Это то, что показывал диалог, плюс дата и просмотр.
3. **Блок «Откуда файл»**: страница, откуда скачано, и канал автора, обе строки
   с адресом и обе открываются в браузере. Блок не прячется у файла без
   метаданных, а говорит прямым текстом, почему он пуст: спрятанный блок не
   отличить от «экран не умеет это показывать».
4. **Действия** переезжают на экран: открыть или скачать, удалить с устройства,
   удалить из шары. Последнее по-прежнему видно только с правом записи в
   токене и по-прежнему спрашивает подтверждение (XR-250), эту защиту не
   ронять.

Тексты в макете сняты с кода дословно, менять их не надо.

## Сценарий проверки

Агентский, на эмуляторе. Стенд поднимается по
[local-docs/android-stand/README.md](../../local-docs/android-stand/README.md),
снапшот эмулятора `xr-ready`, приёмы работы с `uiautomator` в памяти проекта.
В шаре стенда нужен файл, импортированный через агента по ссылке (метаданные
заполнены целиком), файл с суффиксом `[id]` в имени (одна ссылка, канал пуст) и
файл без метаданных вовсе.

1. У импортированного файла экран информации показывает источник и канал,
   адреса видны целиком.
2. Тап по ссылке канала уводит в браузер: проверяется тем, что система
   поднимает `Intent` (в дереве появляется окно выбора или браузер), а не тем,
   что «строка выглядит как ссылка».
3. У файла, скачанного до этой цели, тот же экран показывает либо одну ссылку
   на ролик без канала, либо честный текст про то, что источник неизвестен.
4. Удаление из шары с экрана по-прежнему спрашивает подтверждение, а без права
   записи в токене этого действия на экране нет.

Вывод команд и снимки дерева класть в файл задачи реальные, а не пересказом.
