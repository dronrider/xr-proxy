# XR-190: Реализация LLD-33 фаза 3 (web и приложение): вшитая web-страница шары у агента (просмотр md, история и дифф, правка по write-токену), роуты git/log и git/diff, weblink, экран истории в Android. Зависит от фаз 1-2

## Что происходит

Web-морды у шары нет, ссылка xrshare:// понятна только приложению, открыть
шару с чужого ноутбука нельзя. Git-контур фазы 1 слит (XR-188), репозиторий с
авто-коммитом, транспорт и подписанный HEAD живут у агента, но история и дифф
видны только штатному git-клиенту соавтора. Дизайн страницы и экранов истории
согласован в [LLD-33](../lld/33-share-git-sync.md) п. 2.8, это третья,
завершающая фаза линии. Зависимость от фазы 2 (XR-189) снята словом владельца,
роутам и странице фазы 3 нужен только репозиторий фазы 1, харнесс им не
требуется, работы идут параллельно в разных деревьях.

## Чего хотим

- Роут `GET /{share_id}/web` отдаёт одностраничник, вшитый в бинарь агента,
  без CDN и внешних запросов. Дерево файлов собирается из манифеста, рендер
  md идёт на клиенте. Read-токен даёт просмотр текущего состояния поверх
  существующих роутов manifest/file.
- Write-токен открывает историю, дифф и точечную правку в textarea через тот
  же PUT с If-Match, при 412 страница предлагает перечитать. Под историю и
  дифф заводятся два JSON-роута за scope share:write,
  `GET /{share_id}/git/log?path=&limit=` и
  `GET /{share_id}/git/diff?from=&to=&path=`, оба спавном git.
- Команда `xr-share weblink --invite --share` печатает web-ссылку держателю
  write-гранта из уже выданного ему токена. Минт не трогается, новых каналов
  выпуска write-скоупа не появляется, в выводе стоит предупреждение про
  историю браузера.
- В Android добавляются JNI `nativeGitLog`, экран истории и мелкая правка
  файла через существующий PUT-контур с If-Match, плюс пункт «Открыть в
  браузере» из write-гранта.

Оба ловятся первым живым открытием страницы, сценарий фазы 3 по LLD-33 п. 6 не прогонялся. После моих правок cargo test -p xr-share зелёный.
- блокирует: xr-share/src/server.rs, query_param (стр. 745) не декодирует percent-encoding (комментарий оправдывал это hex/digits старых git-роутов), а параметр path несут оба новых клиента закодированным: страница шлёт encodeURIComponent(path) в git/log и git/diff, xr-core sync.rs git_log_with кладёт его через reqwest .query(). Для файла в подпапке (docs/notes.md уходит как docs%2Fnotes.md) git фильтруется по несуществующему имени: история и дифф пусты, при том что страница всегда фильтрует по текущему файлу (loadHistory/showDiff). Работает только корень шары. Проверить: коммит в подпапке + GET /{id}/git/log?path=docs%2Fnotes.md. Правка: percent-decode параметра path (400 на битой последовательности) и тест с путём в подпапке у обоих роутов.
- блокирует: FilesViewModel.openHistory/openEditor (стр. 1095, 1121): колбэки onSuccess/onFailure не сверяют ответ с актуальным состоянием (historyPath/editPath == entry.path). Поздний ответ старого запроса перезаписывает экран истории другого файла (чужие коммиты), а в редакторе editText заполняется содержимым предыдущего файла: закрыл правку A, открыл правку B, поздний ответ A лёг в поле, сохранение уносит содержимое A в файл B с живым If-Match от B. Гонка реальна на медленной сети (readShareText качает файл до 60 с). Правка: guard в _ui.update, обновлять состояние только при совпадении пути, как страница делает state.current !== path в select().
- не блокирует: xr-share/src/server.rs git_log (стр. 1040): на шаре с включённым git-контуром, но без единого коммита (unborn main, случай пустой папки при share --git; /git/head для unborn возвращает пустую строку, значит случай признан) спавн git log выходит 128 и роут отвечает 500 «git log failed». Страница на boot-пробе ставит hasHistory=false и прячет историю до перезагрузки, приложение в openHistory показывает отказ загрузки. Пустая история это не ошибка: вернуть [] (по пустому refs/heads/main до спавна или распознав stderr про unborn) с тестом на репозитории без коммитов.
