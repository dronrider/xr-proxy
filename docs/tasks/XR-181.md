# XR-181: pull-to-refresh стандартом приложения

Владелец заметил на проверке XR-055, что потягивание экрана вниз не обновляет
список, и потребовал закрепить жест как механику по всему приложению, чтобы
больше про это не напоминать. Поглощает XR-125 (свайп-вниз на списке шар).

## Что сделано

Переиспользуемый `XrPullToRefresh`
([ui/components/XrPullToRefresh.kt](../../xr-android/app/src/main/java/com/xrproxy/app/ui/components/XrPullToRefresh.kt))
поверх Material3 `PullToRefreshBox`. Разложен по всем сетевым спискам:

- список шар по инвайту (`refreshHub`, флаг `loadingHub`) это XR-125;
- проводник шары (`refreshManifest`, `manifestLoading`), контент приведён к
  всегда-скроллящемуся LazyColumn, чтобы жест ловился и на пустой папке;
- карточка пресета на экране правил (`refreshPresetNow`, локальный `refreshing`).

Индикатор жеста рисует тот же флаг загрузки, что гасил кнопку «Обновить»,
поэтому дублирующие инлайн-спиннеры убраны, а кнопки в шапке остались дублёром.
Ради жеста уже поднятый в XR-055 Material3 1.3 (BOM 2025.06.00) дал стабильный
`PullToRefreshBox`, отдельного подъёма не потребовалось.

Конвенция зафиксирована в [ARCHITECTURE.md](../ARCHITECTURE.md) раздел 4.6:
новый сетевой список подключает жест сразу, отдельной задачи не заводить. Экраны
без сетевого источника (главная с Connect, живой журнал) жест не несут.

## Сценарий проверки (пользовательский)

1. Файлы -> «Мои шары»: потянуть список вниз. Появляется индикатор, список
   перезапрашивается по инвайту (как кнопка обновления в шапке).
2. Открыть шару, в проводнике потянуть вниз: манифест перезапрашивается у
   агента. Работает и в пустой папке.
3. Серверы -> «Правила маршрутизации»: потянуть вниз. Пресет хаба
   перечитывается, снекбар про обновление или актуальность.
4. Кнопки «Обновить» в шапках работают как раньше, двойных спиннеров нет.
