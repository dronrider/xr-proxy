# XR-278: Цель: подготовка приложения к iOS-порту, механическая часть: i18n, UX-долги ленты и очередей, тонкий клиент, спайк iOS-сборки ядра, ревизия переносимости бэклога

## Цель

Довести Android-приложение до состояния, из которого iOS-порт пишется без
переделок: тексты в ресурсах, поведенческие UX-долги закрыты, бизнес-логика
из Kotlin инвентаризована и переносимое уехало в xr-core, сборка ядра под iOS
проверена спайком, андроид-специфичное в бэклоге помечено. Дизайновая линия
(XR-058 -> XR-261 -> XR-274, решение по XR-273) в цель не входит и идёт живыми
чатами с пользователем.

DoD: `taskctl show <ID>` печатает «в архиве» для каждой задачи из раздела
«Задачи цели»; задачи-находки, заведённые по ходу, либо тоже в архиве, либо
названы в «Итоге» с причиной, почему остаются на доске.

## Бюджет

бюджет: week_all <= 30
бюджет: week_max <= 10

Потолка яруса нет: вердикт `agentctl pick` работает как обычно.
