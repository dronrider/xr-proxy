# XR-238: xr-hub не собирается в чистом клоне: rust-embed вшивает admin-ui/dist, а каталог гитигнорнут и появляется только после npm-сборки. В свежем worktree крейт не компилируется, пока dist не скопируешь из основного чекаута; лечится build.rs (собрать UI или положить заглушку с внятной ошибкой)

## Разбор корня

`Asset` в [embed.rs](../../xr-hub/src/embed.rs) вшивал каталог по неизменному
пути, `#[folder = "admin-ui/dist"]`, а сам каталог гитигнорен
([admin-ui/.gitignore](../../xr-hub/admin-ui/.gitignore)) и появляется только
после `npm run build`. В свежем чекауте его нет, и rust-embed валит компиляцию
прямо на derive:

```
error: #[derive(RustEmbed)] folder '/private/tmp/xr238-old/xr-hub/admin-ui/dist' does not exist
```

Дальше сыплется `Asset::get` (трейт не реализован), крейт не собирается вовсе.
Бьёт это не только по сборке хаба: `cargo test --workspace` тянет `xr-hub`, а
значит в свежем worktree не проходят и тесты чужих крейтов. Лечили это руками,
копированием `dist` из основного чекаута.

Старый [build.rs](../../xr-hub/build.rs) от этого не спасал: он проверял наличие
`admin-ui/dist/index.html` только в профиле `release`, то есть ровно там, где
собранный UI и правда обязателен, а отладочную сборку с тестами оставлял
компилятору с его невнятным сообщением.

## Что сделано

Каталог для вшивания выбирает build.rs и отдаёт его через `XR_HUB_UI_DIR`,
откуда путь берёт `#[folder = "$XR_HUB_UI_DIR"]` (у `rust-embed` за подстановку
отвечает фича `interpolate-folder-path`). Собран admin UI, вшивается он; нет его
и профиль отладочный, в `OUT_DIR` пишется заглушка на одну страницу, и крейт
собирается без npm и без сети. Релизная сборка заглушки не допускает, она
по-прежнему падает и называет команду сборки UI.

Хаб с заглушкой не притворяется рабочим. Флаг `XR_HUB_UI_PLACEHOLDER` доезжает
до `EmbeddedSpa`, и такая сборка на любой путь админки отвечает `503` с текстом
про несобранный UI, а на старте пишет о том же в лог предупреждением. Пустая
админка тогда не читается как «сервис поднялся, просто страница белая».

Логика выбора живёт отдельным файлом [ui_dist.rs](../../xr-hub/src/ui_dist.rs),
build.rs подключает его через `include!`, а крейт как `#[cfg(test)] mod`. Тесты
гоняют ровно тот код, что принимает решение на сборке, и при этом в боевом
бинаре из него ничего не остаётся.

Дока: устройство описано в `docs/ARCHITECTURE.md` (раздел 5.3, рядом с
рассказом про `rust-embed`), а в `CLAUDE.md` рядом с командами сборки добавлено,
что свежий чекаут тестируется без npm.

## Проверка красноты и мутации

Регрессия здесь это несобирающийся крейт, обычным тестом её не поймать, поэтому
краснота снята сборкой в заведомо чистом дереве: `git worktree add -d
/private/tmp/xr238-old c875447~1` (в отдельном worktree `admin-ui/dist` нет по
определению, он гитигнорен).

```
$ cd /private/tmp/xr238-old && cargo test -p xr-hub
error: #[derive(RustEmbed)] folder '/private/tmp/xr238-old/xr-hub/admin-ui/dist' does not exist
error: could not compile `xr-hub` (bin "xr-hub" test) due to 3 previous errors

$ cd /private/tmp/xr238-new && cargo test --workspace   # тот же приём на ветке
test result: ok. 71 passed  (xr-hub, из них 5 новых)
14 наборов ok, grep по warning: пуст
```

Мутации, каждая гонялась отдельно с восстановлением файлов, `cargo test -p
xr-hub` без собранного `dist` (то есть в обстановке бага):

| Мутация | Кто краснеет |
|--------|--------------|
| M1: старые `build.rs` и `embed.rs` (возврат поломки) | крейт не компилируется, тестов нет вовсе |
| M2: `pick` не смотрит на профиль, релиз тоже получает заглушку | `release_build_without_dist_refuses_and_names_npm` |
| M3: заглушки нет, отладочная сборка тоже отказывается | сборка крейта падает; при собранном `dist` краснеет `debug_build_without_dist_gets_placeholder` |
| M4: собранный `dist` игнорируется | `built_dist_wins_in_both_profiles` |
| M5: заглушка пишет пустую страницу | `placeholder_page_lands_on_disk_and_names_the_reason` |
| M6: снята проверка `placeholder` в `call()` | `placeholder_build_refuses_instead_of_serving_empty_ui`, `unknown_path_still_serves_spa` |
| M7: заглушка отвечает `200` вместо `503` | те же два |
| M8: build.rs не помечает сборку заглушечной | `unknown_path_still_serves_spa` |

M8 краснеет только в дереве без собранного UI: с настоящим `dist` пометка и так
снята, и мутация ничего не меняет. Это ровно тот случай, ради которого правка
делалась, поэтому мутация гонялась в чистом дереве, а не в рабочем.

Тест `unknown_path_still_serves_spa` из `api/mod.rs` пришлось развести по
`UI_PLACEHOLDER`: он проверяет, что неизвестный путь проваливается в SPA, а чем
именно та отвечает, решает наличие UI на сборке. Ждать `200` с заголовком
админки в дереве без npm нечестно.

Времени и гонок в новых тестах нет, заглушка пишется в `tempfile::tempdir`.

## Сценарий проверки

Шаги агентские, живого стенда не требуют.

1. Чистое дерево без admin UI: сборка и тесты встают с нуля.

   ```
   git worktree add -d /private/tmp/xr238-new <ветка или main после слияния>
   cd /private/tmp/xr238-new && cargo test --workspace
   ```

   Обязано быть зелено (в `xr-hub` 71 тест), в выводе нет строк `warning:`.
   Прогнано: 14 наборов ok, warning пусто. На коммите до правки то же место
   даёт `error: #[derive(RustEmbed)] folder ... does not exist`.

2. Релиз без UI по-прежнему отказывается, и в отказе есть команда сборки:

   ```
   cargo build --release -p xr-hub   # в дереве без admin-ui/dist
   ```

   Прогнано: `panicked at xr-hub/build.rs: admin UI не собран: нет
   xr-hub/admin-ui/dist/index.html. Собрать: cd xr-hub/admin-ui && npm ci &&
   npm run build`.

3. Хаб, собранный с заглушкой, виден снаружи. Поднять отладочный бинарь на
   конфиге с `bind = "127.0.0.1:18238"` и пустым списком админов, дёрнуть
   `curl -i http://127.0.0.1:18238/`. Прогнано:

   ```
   HTTP/1.1 503 Service Unavailable
   admin UI не собран: бинарь собран без admin-ui/dist. Собрать: cd xr-hub/admin-ui && npm ci && npm run build
   WARN xr_hub: admin UI не вшит, внутри заглушка: собрать cd xr-hub/admin-ui && npm ci && npm run build
   ```

4. Настоящий UI вшивается как раньше. Положить собранный `dist` в
   `xr-hub/admin-ui/`, прогнать `cargo test -p xr-hub` и
   `cargo build --release -p xr-hub`. Прогнано: 71 тест ok (в том числе
   `unknown_path_still_serves_spa` в ветке с `200` и заголовком админки),
   релизный бинарь собрался.
