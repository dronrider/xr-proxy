# XR-256: Строка списка файлов: имя в две строки вместо эллипса, заметный признак просмотрено, фильтр непросмотренных

Задача цели [XR-253](XR-253.md), пункты 1 и 3 постановки. Рисуется по макету
XR-254, который владелец уже посмотрел и утвердил.

## Что делает владелец сейчас

Имя файла живёт в одну строку с эллипсом посередине
([FilesScreen.kt:995](../../xr-android/app/src/main/java/com/xrproxy/app/ui/files/FilesScreen.kt#L995)),
и от длинного имени ролика видно начало да расширение. Признак просмотра это
серый `Icons.Default.Visibility` слева от имени, владелец его почти не видит.
Отобрать одни непросмотренные нечем.

## Что сделать

Утверждённый макет: страница «Проводник шары» проекта Claude Design
«Мобильное приложение шар», фреймы 2 (список), 3 (замер высоты и меню вида) и 5
(фильтр включён).

1. **Имя в две строки.** `maxLines = 2` с обычным `TextOverflow.Ellipsis` в
   конце вместо `MiddleEllipsis`. Высота строки от этого не растёт: её держит
   `IconButton` справа со своими 48dp (Material3 сам оборачивает его в
   `minimumInteractiveComponentSize`), а колонка имени растёт с 27dp до 42dp и
   в этот запас укладывается. Проверить это на живом экране, а не поверить
   расчёту.
2. **Признак просмотра, вариант Б.** Владелец выбрал точку у непросмотренного:
   круг 7dp цветом `primary` в тех же 14dp левого отступа колонки, где сейчас
   пусто, имя ширины не теряет. Признак меняет смысл на обратный: метится то,
   что ещё не смотрели, а у просмотренного место остаётся пустым. Серый глазок
   убирается совсем.
3. **Фильтр непросмотренных.** Пункт-галочка «Только непросмотренные» в меню
   вида под иконкой в шапке (само меню заводит XR-258, здесь оно появляется с
   одним этим пунктом). Включённый фильтр говорит о себе строкой под шапкой со
   счётчиком вида «Только непросмотренные, 5 из 24» и крестиком, который его
   снимает: без такой строки короткий список не отличить от пропавших файлов.
   Выбор живёт между запусками там же, где порядок строк и отметки просмотра
   ([ShareStore](../../xr-android/app/src/main/java/com/xrproxy/app/data/ShareStore.kt)),
   и он общий на все шары, как и сортировка.

Заодно поправить разделитель в строке статуса: сейчас код пишет дефис
(`"$date - $status"`), а карточка шары и весь макет используют среднюю точку.

Тексты в макете сняты с кода дословно, менять их не надо.

## Сценарий проверки

Агентский, на эмуляторе (AVD `xr-test`, снапшот `xr-ready`, приёмы работы с
`uiautomator` в памяти проекта; тапать по координатам вслепую нельзя, брать
центр `bounds` из дерева):

1. В шаре с длинными именами роликов длинное имя видно в две строки целиком,
   эллипса посередине нет. Дерево `uiautomator` показывает полный текст имени.
2. Высота строки списка выросла не больше чем на треть: `bounds` строки до
   правки и после сравниваются по числам, а не на глаз.
3. У непросмотренного файла в строке есть точка, у просмотренного её нет.
   Открыть файл, вернуться в список, увидеть, что точка пропала.
4. Включить фильтр «Только непросмотренные»: в списке остаются одни
   непросмотренные, под шапкой видна строка со счётчиком, крестик её снимает.
   Убить приложение и открыть заново: фильтр остался включённым.

Вывод команд и снимки дерева класть в файл задачи реальные, а не пересказом.

## Ход работы

- Исполнение: субагент opus/high по вердикту pick (квота: week_all 19%, снимок 30м назад, сдвига нет), 2026-08-04.
- Код написан по фреймам 2, 3 и 5 макета: точка 7dp цветом `primary` в колонке
  метки шириной 14dp, имя `maxLines = 2` с `lineHeight = 15.sp` (13sp на 1.18
  из макета, без этого две строки не влезают в 48dp кнопки и строка растёт),
  меню вида под иконкой `Tune` с единственным пунктом-галочкой, строка-плашка
  под шапкой со счётчиком и крестиком, флаг фильтра в `ShareStore` рядом с
  порядком строк. Разделитель строки статуса переведён на среднюю точку
  константой `SEP`.
- Первый заход упёрся в снесённое Android-окружение (ни SDK, ни JDK, ни AVD);
  диспетчер его восстановил и пересоздал `xr-test`, снапшот `xr-ready` пришлось
  собирать заново.

### Стенд

Боевые данные не нужны, стенд локальный: хаб `xr-hub` на `127.0.0.1:18080`
(свой `signing_key`, админ заведён `hash-password`), агент `xr-share` на
`0.0.0.0:18443` с шарой из семи файлов, среди них длинные имена роликов и файл
с ютуб-суффиксом `[dQw4w9WgXcQ]`. Агент привязан к инвайту одним
`install --setup`, шара зарегистрирована `share --addr <алиас хоста>` (из эмулятора
хост виден по своему стандартному алиасу).

Онбординг по ссылке на таком стенде не проходит: `parse_invite_link`
(`xr-proto/src/invite_url.rs`) принимает только `https` и отвергает приватные
адреса, приложение отвечает «Неправильный формат приглашения». Профиль поэтому
положен прямо в prefs отладочной сборки, дальше приложение само сходило в хаб
за грантом:

```
$ adb shell run-as com.xrproxy.app cat .../shared_prefs/xr_proxy.xml
<string name="servers">[{"id":"stand-1", ... "hub_url":"http://<алиас хоста>:18080",
  "invite_token":"doa120Vjlj_S07F0nLkIEg","source":"Invite"}]</string>
```

Экран «Файлы» после этого показал шару «Разбор на пальцах» из локального хаба,
она добавлена, два файла скачаны, один открыт (то есть просмотрен). Снапшот
эмулятора с этим состоянием сохранён именем `xr-ready` для XR-257 и XR-258;
хаб и агент это процессы хоста, их перед прогоном надо поднять заново
(конфиги в scratchpad-каталоге стенда).

### Пункт 2: высота строки числами

Мерено на одном и том же стенде, `uiautomator dump` до и после подмены APK
(плотность 420dpi, 1dp = 2.625px). До, сборка main (`g9f62bed`):

```
'Вечерний эфир от 26 июля. Ответы на вопросы подписчиков бе'
    bounds=[32,574][1048,716]  высота=142px = 54.1dp  подпись=['8/4/26 - 8.0 КБ']  desc=['Скачать']
'Заметка.txt'
    bounds=[32,719][1048,861]  высота=142px = 54.1dp  подпись=['8/4/26 - 64 Б']
'Как перестать откладывать и начать делать. Разбор на живых'
    bounds=[32,864][1048,1006]  высота=142px = 54.1dp  desc=['Просмотрено', 'Удалить с устройства']
```

После, сборка ветки (`g814f414`), тот же список. В выводе стояла настоящая
средняя точка, здесь она записана escape-последовательностью, как и в коде:

```
'Вечерний эфир от 26 июля. Ответы на вопросы подписчиков бе'
    bounds=[32,574][1048,733]  высота=159px = 60.6dp  подпись=['8/4/26 \u00B7 8.0 КБ']  desc=['Не просмотрено', 'Скачать']
'Заметка.txt'
    bounds=[32,736][1048,878]  высота=142px = 54.1dp  подпись=['8/4/26 \u00B7 64 Б']  desc=['Не просмотрено', 'Скачать']
'Как перестать откладывать и начать делать. Разбор на живых'
    bounds=[32,881][1048,1040]  высота=159px = 60.6dp  подпись=['8/4/26 \u00B7 4.0 КБ \u00B7 скачано, тап откроет']
```

Строка с длинным именем выросла со 142px до 159px, то есть с 54.1dp до 60.6dp,
на 12%. Строка с коротким именем осталась ровно прежней, 142px. Обещание макета
«высота не растёт» строго не сбылось: две строки по 15sp плюс подпись немного
перевешивают 48dp кнопки. Порог цели (не больше трети) выдержан с запасом.

### Пункты 1, 3 и 4

Пункт 1. Узел имени в дереве стал двухстрочным, `[69,582][922,662]` это 80px
против 63px однострочного до правки, и на снимке экрана имя видно целиком, без
эллипса посередине. Ютуб-суффикс по-прежнему срезается: в папке «видео» строка
зовётся `Старый ролик про NAT и пробитие портов.mp4`.

Пункт 3. У непросмотренного файла в дереве появился узел с `content-desc`
«Не просмотрено» размером 18px (6.9dp, это те самые 7dp) в левой колонке
`[42,645][60,663]`, у просмотренного его нет. После открытия файла
«Что делать, если сервис молчит...» и возврата в список точка у него пропала, у
остальных осталась:

```
'Что делать, если сервис молчит. Короткая инструкция для св'
    bounds=[32,1188][1048,1347]  подпись=['8/4/26 \u00B7 2.0 КБ \u00B7 скачано, тап откроет']  desc=['Удалить с устройства']
'Конспект по разбору бюджета семьи за июль.pdf'
    bounds=[32,1043][1048,1185]  подпись=['8/4/26 \u00B7 1.0 КБ']  desc=['Не просмотрено', 'Скачать']
```

Пункт 4. Пункт «Только непросмотренные» в меню под иконкой вида включает фильтр:
в списке остаются три непросмотренных файла из пяти плюс папка, под шапкой
встаёт плашка со счётчиком, а иконка вида меняет описание:

```
'[desc] Вид, фильтр включён' bounds=[954,310][1017,373]
'Только непросмотренные \u00B7 3 из 5' bounds=[58,417][943,480]
'[desc] Снять фильтр' bounds=[943,386][1069,512]
```

`am force-stop` и повторный запуск оставляют фильтр включённым (плашка и
описание иконки те же), а тап по крестику его снимает: плашка уходит, иконка
снова «Вид», в списке опять пять файлов.
