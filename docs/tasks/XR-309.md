# XR-309: Mac подключается к XR через utun без учётки Apple Developer

## Что происходит

При развёртывании XR-300 на MacBook 2026-10-20 приложение удалось собрать
после локальных исправлений Xcode-проекта и Swift-кода. Запустить VPN нельзя.
У владельца доступна только бесплатная Personal Team, которая не выдаёт
разрешение Network Extension. Проблему с аккаунтом Apple сейчас решить
не получается. В разговоре 2026-10-21 пользователь выбрал временный путь
без Network Extension.

Ядро xr-core, UDP relay и IPv6 реализованы в XR-300, XR-301 и XR-302.
Не хватает способа передавать ядру IP-пакеты Mac и управлять сетью без
Network Extension. Ограничение Apple подтверждено
[ответом DTS](https://developer.apple.com/forums/thread/128767).

## Чего хотим

Mac подключается к существующему XR-серверу через фоновый сервис с прямым
utun-интерфейсом. Для установки достаточно локальных прав администратора.
Платная Apple Developer Program и разрешение Network Extension не нужны.
Сервис использует общее Rust-ядро и запускается через launchd.

Пользователь устанавливает, проверяет, останавливает и удаляет сервис
командами из инструкции. Диагностика показывает состояние туннеля и причину
ошибки. При потере туннеля обычный трафик Mac не выходит напрямую.

## Границы

- Это временный способ запуска XR на собственном Mac. Существующий путь
  XR-300 через Network Extension сохраняется.
- В туннель идут TCP и UDP, IPv4 и IPv6. DNS обслуживается через туннель.
  Политика XR-300 по срезу QUIC сохраняется.
- Отдельная реализация транспорта, обфускации, DNS-ядра и UDP relay не нужна.
  Сетевую обвязку macOS отделить от общего xr-core.
- Установка на Mac одной строкой из XR-304 и выпуск через App Store
  в эту задачу не входят. Нужен воспроизводимый локальный установщик.
- Локальные исправления сборки XR-300 уже в main (bcfebe09..738719a7).
  Перед разработкой свериться с их составом и использовать только необходимое.
- Apple предупреждает об ограниченной поддержке прямого utun и PF.
  Совместимость и очистка сетевых настроек проверяются на живом Mac:
  [пояснение DTS](https://developer.apple.com/forums/thread/741544).

## DoD

1. На MacBook владельца без платной учётки Apple установлен и работает
   фоновый XR-клиент через utun. Установка и обновление воспроизводимы
   командой; секреты не попадают в репозиторий, аргументы процесса и лог.
2. Приложения без настройки прокси выходят через XR. Проверены TCP, UDP,
   IPv4, IPv6, DNS и срез QUIC. При отсутствии IPv6 на выходе нет прямой
   утечки IPv6 с Mac.
3. При недоступном сервере, обрыве туннеля и аварийном завершении процесса
   обычный трафик не получает прямого выхода. Путь к самому XR-серверу
   остаётся доступен для восстановления туннеля.
4. После сна, смены Wi-Fi и перезагрузки сервис восстанавливает соединение.
   Проверено окно до запуска сервиса. В нём нет прямого выхода трафика,
   который должен идти через XR.
5. Штатные остановка и удаление возвращают доступ к сети и прежние настройки
   DNS и маршрутов. Команда восстановления работает после аварийного
   завершения. Чужие VPN-профили и правила не удаляются.
6. Есть проверка совместимости с установленным на Mac другим VPN. Если
   одновременный запуск не поддержан, запуск сервиса отклоняется до изменения
   сети с указанием причины.
7. Инструкция описывает установку, права администратора, диагностику,
   восстановление сети и удаление. Проверка на MacBook владельца пройдена,
   вывод диагностических команд приложен к задаче.

## Ранг

50+8+3+0+4 = 65, P1.

- Серьёзность 50: основной сценарий на Mac недоступен, выбранный ранее путь
  требует недоступной сейчас учётки Apple.
- Ценность 8: весь трафик Mac проходит через XR без настройки приложений.
- Неопределённость 3: выбран utun, нужно определить управление маршрутами,
  DNS и блокировкой прямого выхода на macOS.
- Поправка на баг 0: добавляется другой способ запуска клиента.
- Рычаг 4: появляется рабочий путь развёртывания и проверки XR на Mac.

## Приёмка

- вид: mixed
- барьер «доступ»: установка привилегированного сервиса и проверка сна,
  перезагрузки и смены сети на основном MacBook владельца требуют его участия.
  - эмулятор: годится для части автоматики, не подтверждает сетевое
    поведение установленного сервиса на MacBook.
  - синтетическая среда: годится для отказов команд и очистки настроек,
    не подтверждает отсутствие утечек при загрузке настоящей macOS.
  - вторая машина контура: годится для внешнего наблюдения пакетов,
    не заменяет установку и проверку на MacBook владельца.
  - стенд с подменой сети: годится для воспроизводимых обрывов после выката,
    не заменяет сон и перезагрузку физического MacBook.

## Сценарий проверки

Агентская часть после установки: снять состояние сервиса, utun, маршрутов,
DNS и блокировки прямого выхода; проверить внешний адрес и обмен TCP/UDP
с тестовым сервером. Наблюдением на внешнем интерфейсе проверить отсутствие
прямых DNS-запросов и обхода туннеля по IPv4/IPv6. Повторить при обрыве
соединения и аварийном завершении процесса. Конкретные команды и ожидаемый
вывод зафиксировать при выборе интерфейса сервиса.

Совместно с владельцем: установить сервис, проверить сон, смену Wi-Fi,
перезагрузку и соседний VPN. Затем выполнить штатную остановку, повторный
запуск и удаление. Проверить восстановление исходных DNS и маршрутов,
отсутствие оставшихся правил XR и доступ к сети после удаления.
