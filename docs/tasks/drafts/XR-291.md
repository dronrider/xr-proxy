# XR-291: Роутерный выкат мимо автоматики: merge везёт только xr-server

записан 2026-09-04
приоритет: средний

## Черновик

### Ситуация

Ключ `deploy` в .devkit/deploy.local катит xr-server на VPS, а правки xr-client
автоматический выкат из `shipctl merge` на роутеры не привозит. На XR-285 (резолв
внутрь туннеля) раскатка шла руками через .devkit/deploy-router.sh, и перевод
dnsmasq тоже руками теми же uci-командами, что ставит шаг dnsmasq:tunnel. В
автономном режиме это дыра: merge отчитается выкатом, а на роутерах остаётся
старый бинарь.

Вопрос: как развести в deploy.local два адресата выката, чтобы merge сам выбирал
роутерный путь по тому, какое приложение тронуто.

Гипотеза: отдельный ключ вроде deploy_xr_client рядом с deploy и deploy_xr_hub,
раз такой ключ для хаба уже есть.
