# XR-312: MPTCP объединяет WAN для одной загрузки через XR

записан 2026-10-29
приоритет: средний

## Черновик

### Ситуация

В обсуждении XR-310 от 29 октября 2026 пользователь уточнил, что хочет скачивать один файл в браузере с использованием обоих интернет-каналов. Сейчас xr-client распределяет отдельные соединения между WAN во взвешенном пуле. Один поток остаётся на выбранном канале. Подключения пользователя имеют скорости 100 и 300 Мбит/с; сумма каналов нужна и для одной загрузки, а не только для совокупности соединений.

### Осложнение

Распределение соединений не позволяет одной однопоточной загрузке использовать суммарную пропускную способность двух провайдеров. Ускорение обработки XR и увеличение числа туннелей сами по себе этого ограничения не снимают. Получение около 400 Мбит/с через интернет для одной загрузки пока не подтверждено.

### Вопрос

Поддерживают ли ядра целевого OpenWRT и VPS MPTCP, какие пакеты, настройки маршрутизации и изменения сокетов потребуются? Можно ли использовать MPTCP как транспорт между xr-client и xr-server, сохранив обфускацию, мультиплексирование и правила выбора WAN? Как обнаруживать отсутствие поддержки и переходить на обычный TCP? Как сохранить работоспособность при отказе одного провайдера и не нарушить DNS, конфиденциальность и действующие правила маршрутизации? Хватит ли производительности роутера и пропускной способности пути через VPS для заметного выигрыша? Как измерить вклад каждого WAN и скорость одной загрузки на контролируемом ресурсе?

### Гипотеза

Пользователь хочет отдельную реализацию MPTCP в экосистеме XR. Один поток браузера использует оба провайдера через транспорт между xr-client и xr-server. Браузер и целевой сайт не требуют изменений. Ожидается приближение к суммарной полезной скорости каналов при достаточной мощности оборудования и скорости внешнего пути, без обещания ровно 400 Мбит/с.

## Контекст обсуждения

Пользователь явно попросил завести черновик реализации MPTCP как отдельной задачи. Разработка в этом заходе не запрошена. Работу следует отделить от реализованного пула соединений XR-310.

В обсуждении предложен MPTCP между роутером и VPS, где агрегацию выполняет ядро Linux, а XR использует этот транспорт. Совместимость с текущими ядрами и кодом пока не проверена. Собственная агрегация блоков внутри протокола XR упомянута как более сложная альтернатива, но пользователем не выбрана. Простое включение MPTCP в ОС нельзя заранее считать достаточным. Необходимо проверить создание сокетов и организацию нескольких путей в XR.

Многопоточная загрузка файла может использовать существующий WAN-пул при поддержке загрузчика и сервера, но не заменяет желаемую поддержку одного потока. Существующие правила по устройству и ресурсу, защищённый DNS, резервирование и конфиденциальность должны сохраниться. Поведение для явно закреплённого WAN предстоит определить при разборе.

По предыдущим измерениям локальный стенд XR достигал около 392-397 Мбит/с после оптимизаций; внешние результаты существенно менялись даже без XR. Эти результаты не доказывают скорость будущего MPTCP и не позволяют заранее назначить единственное узкое место.
