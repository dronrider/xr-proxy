# XR-285: поддельный NXDOMAIN провайдера кладёт сайт раньше перехвата прокси

записан 2026-08-28

## Черновик

### Ситуация

2026-08-28, домашняя сеть за роутером с xr-client: rutracker.org не
открывается. Диагностика с Mac показала подмену DNS у провайдера: на
UDP-запрос приходит NXDOMAIN с флагом aa даже «от» публичных резолверов
Cloudflare и Google, тот же запрос по TCP отдаёт настоящие адреса, а HTTPS
с подставленным вручную адресом работает (TLS 1.3, настоящий сертификат).
Роутерная часть xr-proxy DNS не трогает: nftables исключает порты 53 и 853
из перехвата (xr-client/src/redirect.rs:286-288), решение о проксировании
принимается по SNI уже открытого TCP (xr-client/src/proxy.rs:192-197), а
установщик лишь переводит dnsmasq на Quad9 обычным UDP:53
(xr-setup/src/openwrt.rs:59-87), который перехватывается так же, как
провайдерский.

### Осложнение

Без адреса LAN-клиент не открывает TCP-соединение, и xr-client нечего
перехватывать: заблокированный через DNS сайт лежит на всех устройствах сети
несмотря на работающий туннель, а снаружи это неотличимо от «прокси не
работает». Обещание README про доступ без настройки на устройствах для таких
сайтов не выполняется.

### Вопрос

Каким путём уводить DNS из-под перехвата: локальная заглушка xr-client с
резолвом через туннель на VPS, https-dns-proxy перед dnsmasq или перенос
Fake-IP из xr-core (Android уже так живёт) на роутер?

### Гипотеза

Сайт, заблокированный у провайдера на уровне DNS, открывается с любого
LAN-клиента без настройки на самом устройстве.
