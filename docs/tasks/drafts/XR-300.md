# XR-300: Весь трафик Mac уходит в туннель независимо от настроек приложений

записан 2026-10-13
приоритет: средний

## Черновик

### Ситуация

Макбук работает в двух кейсах. Дома роутер сам заворачивает чувствительный трафик на сервер xr-proxy. В чужой сети идёт подключение через другие точки доступа, и тут возможна утечка. Перехват у xr-client сегодня линуксовый, iptables на OpenWRT. Ядро кроссплатформенное, iOS-спайк уже намечен в docs/lld/39-ios-core-spike.md, слоя для macOS нет. На доске стоит XR-017 «Клиент под macOS».

### Осложнение

Без системного перехвата гарантия падает до «каждое приложение настроено». Один забытый процесс, и запрос уходит с чужой точки доступа.

### Вопрос

Мост через pf отпал ещё до реализации. pf не документирован Apple как публичный путь для приложений. UDP и QUIC требуют своего слушателя, IPv6 свои правила, соседство с другими VPN не закрыто. Решение от 2026-10-13 в пользу минималистичного приложения с Network Extension. Packet Tunnel Provider забирает весь IP-трафик, включая QUIC, и переживает перезагрузки штатно. Открытыми остаются объём минимального набора, ловля DNS внутри туннеля, подпись с нотаризацией. Кольца не будет, туннель до сервера роутером не перехватывается.

### Гипотеза

Mac из любой сети гонит весь трафик через туннель приложения на сервер. Поведение дома и в чужой сети одинаковое. Приложение без настроек не утекает, резолв доменов идёт через туннель. Падение туннеля не открывает прямой выход. Без туннеля соединения рвёт отдельный фильтр.
