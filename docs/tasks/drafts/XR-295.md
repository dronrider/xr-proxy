# XR-295: Раздача интернета с телефона идёт через прокси приложения

записан 2026-09-11
приоритет: средний

## Черновик

### Ситуация

2026-09-11, мысль владельца. На Android приложение работает как VPN. XrVpnService
поднимает TUN, движок xr-core обрабатывает трафик самого телефона (README, раздел
«Android-клиент»). Штатная раздача интернета (точка доступа Wi-Fi, USB, Bluetooth)
идёт мимо TUN. Android пропускает трафик подключённых устройств через NAT прямо в
сотовый аплинк, VpnService его не получает, публичного API завернуть его в туннель
нет. Входа для чужих устройств в коде тоже нет. xr-client слушает только перехват
роутера (xr-client/src/proxy.rs, listen_port), SOCKS и HTTP CONNECT в xr-core и
xr-client отсутствуют, слов tether и hotspot в xr-android нет.

### Осложнение

В поездке без своего роутера ноутбук и второй телефон, подключённые к точке
доступа, остаются без правил пресета. Заблокированное у них не открывается, а
туннель на телефоне им не помогает. Единственный обход сейчас это свой клиент на
каждом устройстве.

### Вопрос

Штатную раздачу без root в туннель не завернуть, поэтому развилка идёт про обход.
Первый вариант. Приложение поднимает на адресе точки доступа локальный SOCKS5 или
HTTP CONNECT прокси поверх того же движка и правил пресета, устройства прописывают
его в настройках сети руками. Через него идёт только трафик, который умеет ходить
через прокси. Браузеры, системный прокси macOS, Windows и iOS, TCP. UDP и
приложения, которые системный прокси пропускают, идут мимо. Второй вариант. На
телефоне с root правила nat перекладывают трафик wlan и rndis в TUN, как это
делает роутер, прозрачно и целиком. Решить, какой вариант брать или оба, и как
устройство узнаёт адрес прокси (QR на экране, страница на телефоне, ручной ввод).

### Гипотеза

Устройство, подключённое к точке доступа телефона, ходит по правилам пресета так
же, как сам телефон, без установки клиента на устройство.
